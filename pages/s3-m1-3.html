SpringMVC 与 RESTful 开发

预计 1 天模块一 · Java / SpringBoot

一、学习目标

  • 能够描述一次 HTTP 请求从 DispatcherServlet 到 Controller 再到响应返回的完整流程。
  • 能够熟练使用 @RestController、@RequestMapping、@GetMapping、@PathVariable、@RequestBody 等注解开发接口。
  • 能够按 RESTful 风格设计资源路径与 HTTP 方法，并返回语义正确的状态码。
  • 能够用 @Valid 完成参数校验，并用统一异常处理输出规范的错误响应体。

二、核心知识点

知识点 1：SpringMVC 请求处理流程

DispatcherServlet 是前端控制器：请求进来后，它把 URL 交给 HandlerMapping 找到对应的 Controller 方法（Handler），再通过 HandlerAdapter 调用方法；方法返回的对象经 MessageConverter（默认 Jackson）序列化为 JSON，写回响应。理解这条链的价值在于排查问题有章法：404 说明 HandlerMapping 没匹配上（检查路径与方法），415/406 说明消息转换器不匹配（检查 Content-Type 与依赖），参数绑定失败是类型转换问题（常见于字符串转枚举、日期格式）。

参数绑定要点：@PathVariable 接路径变量、@RequestParam 接查询参数（可用 defaultValue 与 required 控制）、@RequestBody 接 JSON 请求体（依赖 Jackson）、@RequestHeader 接头信息。Controller 应当薄：只做参数绑定、校验与编排，业务逻辑下沉到 Service。

知识点 2：RESTful 设计与状态码

REST 的核心是把 HTTP 动词当作对资源的操作语义：GET 查询（安全、幂等）、POST 创建、PUT 整体替换（幂等）、PATCH 局部更新、DELETE 删除（幂等）。路径用名词复数表达资源，层级表达从属关系，如 /api/v1/tickets/{id}/comments；版本号放路径前缀便于演进。状态码要如实表达结果：200 成功、201 创建（配合 Location 头）、204 删除成功无返回体、400 参数错误、401 未认证、403 无权限、404 资源不存在、409 冲突、500 服务端异常。错误响应建议统一结构（code/message/requestId），前端与联调都会感谢你。

知识点 3：参数校验与全局异常处理

永远不要相信外部输入。用 Bean Validation 注解（@NotBlank、@Size、@Min、@Pattern）标注 DTO 字段，在入口加 @Valid 触发校验；校验失败会抛 MethodArgumentNotValidException。再用 @RestControllerAdvice 定义全局异常处理器：把业务异常映射为语义化的 4xx、未知异常映射为 500 并记录日志，绝不把堆栈暴露给调用方。这样 Controller 中不再出现 try-catch 样板代码。

三、示例演示

示例一：一个规范的工单 RESTful Controller：

@RestController
@RequestMapping("/api/v1/tickets")
public class TicketController {

    private final TicketService ticketService;

    public TicketController(TicketService ticketService) {
        this.ticketService = ticketService;
    }

    @PostMapping
    public ResponseEntity<TicketVO> create(@Valid @RequestBody CreateTicketReq req) {
        TicketVO vo = ticketService.create(req);
        return ResponseEntity
                .created(URI.create("/api/v1/tickets/" + vo.id()))
                .body(vo);
    }

    @GetMapping("/{id}")
    public TicketVO detail(@PathVariable long id) {
        return ticketService.getById(id);
    }

    @GetMapping
    public PageResult<TicketVO> list(@RequestParam(defaultValue = "1") int page,
                                     @RequestParam(defaultValue = "10") int size) {
        return ticketService.page(page, size);
    }

    @DeleteMapping("/{id}")
    @ResponseStatus(HttpStatus.NO_CONTENT)
    public void delete(@PathVariable long id) {
        ticketService.delete(id);
    }
}

示例二：DTO 校验与全局异常处理，让错误响应也符合规范：

public record CreateTicketReq(
        @NotBlank(message = "标题不能为空") @Size(max = 100) String title,
        @NotBlank(message = "描述不能为空") String description) {
}

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ApiError> handleValidation(MethodArgumentNotValidException ex) {
        String msg = ex.getBindingResult().getFieldErrors().stream()
                .map(f -> f.getField() + ": " + f.getDefaultMessage())
                .collect(Collectors.joining("; "));
        return ResponseEntity.badRequest().body(new ApiError(400, msg));
    }

    @ExceptionHandler(IllegalArgumentException.class)
    public ResponseEntity<ApiError> handleBadRequest(IllegalArgumentException ex) {
        return ResponseEntity.badRequest().body(new ApiError(400, ex.getMessage()));
    }
}
💡 提示：用 curl -i 或 IDEA 的 HTTP Client 检查返回的状态码与响应头是否符合语义（如 201 带 Location）；联调前先用 Spring Boot 的 OpenAPI 依赖生成接口文档，可以大幅减少沟通成本。
