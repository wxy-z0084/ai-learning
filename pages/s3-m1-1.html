Java 语法进阶与集合、多线程

预计 1 天模块一 · Java / SpringBoot

一、学习目标

  • 能够熟练使用泛型、枚举、异常处理写出类型安全、语义清晰的 Java 代码。
  • 能够根据场景选择 List / Set / Map 的具体实现，并说清 hashCode 与 equals 的契约。
  • 能够使用 Thread、线程池 ExecutorService 编写并发任务，理解为何不该自己 new Thread。
  • 能够解释共享变量并发访问的三大问题（可见性、原子性、有序性）与 synchronized、volatile 的作用。

二、核心知识点

知识点 1：泛型、枚举与异常体系

泛型把类型检查提前到编译期：List<String> 让误放 Integer 在编译阶段就报错，避免运行时 ClassCastException；注意泛型存在类型擦除，运行时拿不到 List<String> 里的 String，这也是不能 new T[] 的原因。枚举不仅是常量集合，还能携带字段与方法，适合表达有限状态（如订单状态机）。异常分受检（checked，如 IOException，编译器强制 try 或 throws）与非受检（RuntimeException 及其子类）；业务异常建议自定义并携带错误码，避免用字符串匹配异常信息。原则：只捕获能处理的异常，捕获后要么恢复、要么转译，绝不用空 catch 吞掉。

知识点 2：集合框架

集合三大主力：ArrayList（数组实现，随机访问 O(1)，中间插入 O(n)）、LinkedList（链表，头尾操作快，实际很少用）、HashMap（键值查找 O(1)，最常用的 Map）、HashSet（基于 HashMap 去重）、TreeMap/TreeSet（按自然序或比较器排序）。关键契约：作为 Map 键或放入 HashSet 的自定义对象必须同时重写 hashCode 与 equals——两个相等的对象必须有相同哈希值，否则"存得进却查不出"。并发场景用 ConcurrentHashMap 而不是 Collections.synchronizedMap，读多写少时吞吐差距明显。

知识点 3：多线程与线程池

直接 new Thread 的问题：线程创建销毁开销大、数量无上限、参数无法统一管理。生产代码一律用线程池：核心线程数、最大线程数、工作队列、拒绝策略四大参数，通过 Executors 工厂方法或 ThreadPoolExecutor 显式创建（推荐后者，参数可见可控）。并发访问共享变量会带来可见性（线程 A 改了线程 B 看不到）、原子性（count++ 是读改写三步）、有序性问题，对应手段是 volatile（保证可见性与禁止指令重排，不保证复合操作原子性）、synchronized（互斥 + 可见性）与原子类（如 AtomicInteger）。

三、示例演示

示例一：集合与自定义对象的 hashCode/equals 契约：

import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.Objects;

public class Employee {
    private final String id;
    private String name;

    public Employee(String id, String name) {
        this.id = id;
        this.name = name;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof Employee e)) return false;
        return Objects.equals(id, e.id);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id);   // 只用参与 equals 的字段
    }

    public static void main(String[] args) {
        Map<Employee, Double> salary = new HashMap<>();
        salary.put(new Employee("E001", "张三"), 15000.0);
        // 即使是另一个对象，只要 id 相同就能查到
        System.out.println(salary.get(new Employee("E001", "张三丰")));  // 15000.0
    }
}

示例二：用线程池并发处理任务（模拟批量调用模型接口）：

import java.util.List;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.TimeUnit;

public class BatchTask {
    public static void main(String[] args) throws InterruptedException {
        List<String> questions = List.of("什么是RAG？", "什么是Agent？", "什么是微调？");

        ExecutorService pool = new Executors.newFixedThreadPool(2);
        try {
            for (String q : questions) {
                pool.submit(() -> {
                    System.out.println(Thread.currentThread().getName()
                            + " 处理：" + q);
                    return null;
                });
            }
        } finally {
            pool.shutdown();
            pool.awaitTermination(30, TimeUnit.SECONDS);
        }
    }
}
💡 提示：IDE 中把 new FixedThreadPool(2) 这类 Executors 工厂方法标记为不推荐——它内部使用无界队列，任务堆积会耗尽内存；面试与生产中应显式写 ThreadPoolExecutor 的四个参数。

四、实践任务

  1. 任务 1：写一个 Ticket 类放入 HashSet，先不重写 hashCode/equals 观察去重失效，再补上重写并解释原因。
  2. 任务 2：用 ArrayList、HashMap、TreeMap 各实现一次"按工单号统计各状态数量"，对比代码复杂度与输出顺序差异。
  3. 任务 3：用显式参数的 ThreadPoolExecutor 并发处理 100 个模拟任务，观察核心线程数、队列长度变化对完成时间的影响。
  4. 任务 4（进阶，可选）：写一个多线程对共享 count 做 10000 次自增的程序，分别用 int、volatile int、AtomicInteger、synchronized 验证结果差异。
