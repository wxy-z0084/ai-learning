核心组件：Model / Prompt / Chain

预计 1 天模块四 · LangChain

一、学习目标

  • 能够说清 LangChain 0.2 的包结构（core / 主包 / community / partner 包）以及各层职责。
  • 能够熟练配置和调用 ChatOpenAI 等聊天模型，理解 temperature、max_tokens、timeout 等关键参数的影响。
  • 能够使用 ChatPromptTemplate 构建含系统指令、变量占位、少量示例（few-shot）的提示词模板。
  • 能够把"提示词模板 → 模型 → 输出解析器"用 | 管道组合成可复用的 Chain，并解析出结构化结果。

二、核心知识点

知识点 1：LangChain 0.2 的包结构

LangChain 0.2 起做了清晰拆分：langchain-core 定义最基础的抽象——聊天模型、提示词模板、输出解析器、Runnable 接口，不含任何具体厂商实现；langchain 主包提供链（Chain）、代理（Agent）等编排逻辑；langchain-community 收纳社区维护的第三方集成；langchain-openai、langchain-anthropic 等是各厂商的 partner 包，独立发版、依赖更干净。安装时按需组合：pip install langchain langchain-openai。

0.2 时代要建立的新认知：聊天模型（ChatModel）是一等公民，输入输出都是"消息"而非纯文本；旧教程里的 LLMChain、OpenAI() 文本补全类用法正在退役，官方推荐用 LCEL 管道（prompt | model | parser）替代——这也是下一模块 LCEL 的铺垫。

知识点 2：模型层——ChatOpenAI 的配置要点

所有聊天模型都接收消息列表、返回 AIMessage。ChatOpenAI 的常用参数：model（模型名，如 gpt-4o-mini）；temperature（0～2，越低越稳定，事实问答建议 0～0.3，创作风格类任务可 0.7+）；max_tokens（单次回复上限，防止超长烧钱）；timeout / max_retries（生产必配：网络超时与自动重试）；api_key 与 base_url（可指向 OpenAI 兼容网关）。接入国产模型或本地模型的常见姿势：用 Ollama、vLLM、各厂商的 OpenAI 兼容端点，只改 base_url 即可，代码零改动。

消息分三种角色：SystemMessage（设定身份与规则，权重最高）、HumanMessage（用户输入）、AIMessage（模型历史回复）。调用方式：model.invoke([messages]) 同步调用，model.ainvoke() 异步调用，model.stream() 流式输出。

知识点 3：提示词模板——把"调提示词"变成"改配置"

ChatPromptTemplate 由多条消息模板组成，用 {变量名} 做占位。设计要点：① 系统消息里写清角色、任务边界、输出格式要求；② 用户消息只放动态内容；③ 需要注入 few-shot 示例时，用 MessagesPlaceholder 预留消息列表位置；④ 需要复用不同供应商时，模板与模型解耦是 LangChain 最大的工程价值——换模型不改提示词，改提示词不动业务代码。渲染时传入与占位符一一对应的字典，漏传变量会直接抛出错误（这是好事，能提前暴露问题）。

知识点 4：输出解析器与 Chain 组合

模型返回的是消息对象，要变成业务可用的字符串或结构体，需要输出解析器：StrOutputParser 取出文本；JsonOutputParser 解析 JSON（配合提示词注入格式说明）；with_structured_output(Pydantic模型) 直接得到类型安全的对象，最推荐。把模板、模型、解析器用 | 串起来就是一个 Runnable 链，可直接 .invoke()、.batch()、.stream()。注意：管道里每一步的输出类型必须是下一步期望的输入类型，这是 LCEL 的核心约定。

三、示例演示

示例一：模板 + 模型 + 解析器的标准三段式链，支持流式输出：

# pip install langchain langchain-openai
import os
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

model = ChatOpenAI(
    model="gpt-4o-mini",
    temperature=0.2,
    max_tokens=1024,
    timeout=30,
    max_retries=2,                       # 生产环境必备：失败自动重试
    api_key=os.environ["OPENAI_API_KEY"],
)

prompt = ChatPromptTemplate.from_messages([
    ("system", "你是一名资深{role}。回答要求：先给结论，再给要点，全程使用中文。"),
    ("human", "{question}"),
])

chain = prompt | model | StrOutputParser()   # LCEL 管道：每步输出即下一步输入

answer = chain.invoke({"role": "后端架构师", "question": "FastAPI 的依赖注入该怎么理解？"})
print(answer)

# 流式输出：逐段拿到回答，适合做打字机效果
for token in chain.stream({"role": "后端架构师", "question": "什么是数据库连接池？"}):
    print(token, end="", flush=True)

示例二：用 Pydantic 做结构化输出，让模型直接返回类型安全的对象：

from pydantic import BaseModel, Field

class IssueAnalysis(BaseModel):
    severity: str = Field(description="严重级别：high/mid/low")
    category: str = Field(description="问题类别：性能/安全/可用性/其他")
    suggestion: str = Field(description="改进建议，一句话，不超过 50 字")

structured_model = model.with_structured_output(IssueAnalysis)
result = structured_model.invoke(
    "线上日志出现大量 connection timeout，接口 P99 从 200ms 涨到 3s，请分析。"
)
print(result.severity, result.category, result.suggestion)
# 直接得到 Pydantic 对象，无需手写 JSON 解析和校验逻辑
💡 提示：temperature=0 也不等于完全确定性（服务端可能仍有波动），重要的自动化任务要在解析层做字段校验；切换供应商模型时优先只改 base_url 与 model 名，跑一遍评测集再上线。

四、实践任务

  1. 任务 1：封装一个可复用的 build_chat_model(model_name, temperature) 工厂函数，统一处理 api_key、timeout、重试，并用它跑通一次调用。
  2. 任务 2：写一个"周报生成器"提示词模板：系统消息规定角色与输出格式，用户消息占位符接收本周工作要点列表，用 Chain 生成结构化周报。
  3. 任务 3：用 with_structured_output + Pydantic 实现"从一段用户反馈中提取{情绪, 主题, 优先级}"，批量处理 10 条真实反馈。
