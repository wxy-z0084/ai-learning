包管理与工程化项目结构

预计 0.5 天模块一 · Python 全栈

一、学习目标

  • 能够创建并管理虚拟环境，解释为什么不把包装进系统 Python。
  • 能够读懂并编写 pyproject.toml，声明项目元信息、依赖与可选依赖组，实现依赖可复现安装。
  • 能够搭建一个src 布局的标准项目骨架，说清包目录、入口、配置与测试各放哪里。
  • 能够使用 ruff、mypy 等工具把代码风格与类型检查纳入日常开发流程。

二、核心知识点

知识点 1：虚拟环境与依赖声明

虚拟环境（venv）是项目专属的 Python 解释器 + 独立 site-packages 目录，让 A 项目要 numpy 1.24、B 项目要 numpy 2.0 互不干扰，也避免 pip install 污染系统环境（很多 Linux/macOS 上系统 Python 受保护，直接装还会报错）。标准做法：python -m venv .venv 创建，激活后所有安装都落在项目内；忘记激活是新手最常见的坑，表现为「明明装了却 import 不到」。

依赖声明有两级：直接依赖（你 import 的库）写进 pyproject 的 project.dependencies；精确锁定则由 uv.lock / poetry.lock 或 pip freeze > requirements.txt 记录全部传递依赖的版本，团队与部署环境必须按锁文件安装，否则「我本地能跑」。开发期工具（pytest、ruff、mypy）放在 可选依赖组（[project.optional-dependencies] dev 或 [dependency-groups]），避免污染运行时依赖。

知识点 2：pyproject.toml 与现代打包

pyproject.toml（PEP 518/621）是 Python 项目的统一配置文件，取代了 setup.py、setup.cfg、requirements.txt 三足鼎立的局面，包含 [project]（名称、版本、依赖）、[build-system]（构建后端）、[tool.*]（ruff、mypy 等工具配置）。当前主流工具推荐 uv（Astral 出品，速度极快，一条 uv sync 完成建环境+装依赖）或 Poetry（生态成熟，lock 机制完善）；两者都以 pyproject.toml 为唯一事实来源。

可复现安装的三种姿势：uv sync（读 uv.lock）、poetry install（读 poetry.lock）、pip install -r requirements.txt。而 pip install -e .（可编辑安装）让你改包内源码立即生效、无需重装，是本地开发包项目的必备技巧。

知识点 3：工程化项目结构（src 布局）

推荐 src 布局：包代码放 src/包名/ 下，测试用「安装后的包」而非直接 import 当前目录，能提前暴露漏声明依赖的问题。一个 AI 服务项目的典型结构：src/myapp/{api,core,services,models,utils}.py 放业务代码；tests/ 按 test_*.py 组织；configs/ 或 .env 放配置（密钥用环境变量，严禁提交仓库）；scripts/ 放一次性脚本；根目录放 pyproject.toml、README.md、.gitignore、Dockerfile。核心原则：业务逻辑与入口分离——app/ 只写可复用的函数与类，main.py / uvicorn 启动命令只做装配。

知识点 4：静态质量门禁

工程化的三件套：ruff 替代 flake8+isort+pyupgrade，一条命令完成 lint 与格式化（ruff check --fix / ruff format）；mypy 做静态类型检查，在运行前抓出类型错误；pre-commit 把它们挂在 git commit 上，不合格代码进不了仓库。三者配置全部写进 pyproject.toml 的 [tool.*] 段，团队共享同一份规则。

三、示例演示

一个可直接使用的 pyproject.toml（含依赖、dev 组与工具配置）：

[project]
name = "ai-agent-service"
version = "0.1.0"
description = "智能体后端服务"
requires-python = ">=3.11"
dependencies = [
    "fastapi>=0.115",
    "uvicorn[standard]>=0.30",
    "pydantic>=2.7",
    "httpx>=0.27",
    "sqlalchemy>=2.0",
]

[project.optional-dependencies]
dev = [
    "pytest>=8.0",
    "ruff>=0.5",
    "mypy>=1.10",
]

[dependency-groups]
lint = ["ruff>=0.5"]

[tool.ruff]
line-length = 100
target-version = "py311"

[tool.ruff.lint]
select = ["E", "F", "I", "UP", "B"]

[tool.mypy]
python_version = "3.11"
strict = true
ignore_missing_imports = true

项目结构与初始化命令（用 uv 为例，用 Poetry/pip 只需换安装命令）：

ai-agent-service/
├── pyproject.toml          # 唯一依赖与工具配置入口
├── uv.lock                 # 精确锁定的依赖版本，提交到 git
├── README.md
├── .env.example            # 环境变量样例（不含真实密钥）
├── src/
│   └── myapp/
│       ├── __init__.py
│       ├── api/            # 路由层：只做参数解析与响应
│       ├── services/       # 业务逻辑层：可单测、不依赖框架
│       ├── models/         # 数据模型（Pydantic / ORM）
│       └── core/           # 配置、日志、公共依赖
├── tests/
│   └── test_health.py
└── main.py                 # 启动入口：uvicorn main:app

# 命令序列
uv venv                       # = python -m venv .venv
uv sync --extra dev           # 按锁文件安装依赖 + dev 工具
uv pip install -e .           # 可编辑安装，改源码立即生效
ruff check --fix . && ruff format .
mypy src
💡 提示：把 .venv、__pycache__、.env、*.lock 以外的临时文件写进 .gitignore；锁文件（uv.lock / poetry.lock / requirements.txt）一定要提交，否则团队环境必然漂移。

四、实践任务

  1. 任务 1：新建一个项目目录，用 venv（或 uv）创建隔离环境，安装 fastapi、pydantic、ruff，验证 python -c "import fastapi" 只在该环境内成功。
  2. 任务 2：按 src 布局搭建骨架，写一个可在 myapp.services 中被测试 import 的纯函数，并用 pip install -e . 让测试通过包名而非相对路径导入它。
  3. 任务 3：把直接依赖与 dev 依赖分组写入 pyproject.toml，生成锁文件（uv lock 或 pip freeze），在全新目录按锁文件复现安装并确认版本一致。
  4. 任务 4（进阶，可选）：配置 ruff（line-length=100、启用 I 排序）与 mypy strict，跑通一个模块的检查；再加 pre-commit 钩子让 commit 时自动执行。

五、推荐资源

  • 📖 venv 模块文档（中文） — 虚拟环境的创建、激活与失效场景，环境问题的第一手排查依据。
  • 📖 PyPA Python 打包官方指南 — pyproject.toml、构建后端、发布流程的权威英文资料，装包报错时必查。
  • 📖 uv 官方文档 — 当前最快的 Python 环境与依赖管理工具，含从 pip/poetry 迁移章节。
  • 📖 ruff 官方文档 — 规则列表与 pyproject 配置示例，一行命令完成 lint 与格式化。
  • 📖 PEP 621：pyproject 中的项目元数据 — [project] 表每个字段的官方定义，写配置有歧义时对照它。

六、自检清单

  • 我能解释「装了包但 import 报错」的三种常见原因（未激活环境、装错环境、拼写问题）吗？
  • 我能独立写出一个包含依赖分组与工具配置的 pyproject.toml 吗？
  • 我能按 src 布局把业务逻辑、路由、配置、测试分到正确目录，并说明这样分层的理由吗？
  • 我知道锁文件该不该提交、.env 该不该提交，并能配置好 .gitignore 吗？
