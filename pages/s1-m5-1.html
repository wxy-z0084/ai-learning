阶段一 · 指挥AI写软件

零代码/低代码智能体搭建流程

预计 0.5 天模块五 · AI 智能体快速开发

一、学习目标

  • 能够说清智能体（Agent）与普通聊天机器人的区别，理解其四要素：模型、提示词、知识库、工具。
  • 能够按创建 Bot → 写人设 → 挂技能 → 建知识库 → 调试 → 发布的完整流程搭出一个可用智能体。
  • 能够配置知识库的分段、召回与命中测试，让回答有据可依。
  • 能够使用调试预览与日志定位提示词、知识库、插件三类问题。

二、核心知识点

知识点 1：智能体的四个组成部分

零代码平台上的智能体，本质上是给大模型套上四层配置：模型决定智力上限（复杂推理选旗舰模型，简单客服可选轻量模型以省成本）；提示词定义角色、任务流程与输出格式；知识库提供模型原本不知道的私有资料（产品手册、价目表、规章制度）；工具/插件赋予它动手能力（查库、下单、发邮件、生成图片）。四者职责清晰，调试时才能对症下药：答不上来是知识库问题，答得离谱是提示词问题，说要查却没查是工具配置问题。

知识点 2：人设提示词的骨架

可用的智能体提示词通常包含五块：角色与目标（你是谁、服务谁、衡量标准是什么）、能力边界（能做什么、遇到什么问题该拒答或转人工）、工作流程（先澄清再回答、先查知识库再作答）、输出格式（字数、结构、是否带引用来源）、语气规范（称呼、禁用语）。其中边界条款最能防止翻车——明确写"涉及具体赔偿金额一律引导转人工"，比事后补救省一百倍。

知识点 3：知识库的分段与召回

知识库的作用机制是 RAG：上传文档 → 切成片段并生成向量 → 提问时检索最相关的几段 → 拼进提示词让模型作答。因此切分质量直接决定回答质量。实操要点：按语义分段而非固定字数硬切（200-500 字一段较合适）；给每段配准确的标题与关键词；文档更新后重新上传并做命中测试——用真实用户问题逐条验证能否召回正确段落。召回不稳时，优先调整分段与检索条数，而不是急着换模型。

💡 上线前用"红队思维"试一遍：越界问题、诱导泄露系统提示词、要求给出不存在的信息——看智能体是否按边界条款稳住。

三、示例演示

示例一是一份可直接粘贴到 Coze Bot「人设与回复逻辑」的完整提示词骨架（以咖啡店点单助手为例）：

# 角色
你是「晨光咖啡」的点单助手小晨，帮助顾客了解菜单、推荐饮品、引导下单。

# 目标
让顾客在 3 轮对话内完成点单意向确认；推荐要基于知识库中的在售商品。

# 工作流程
1. 先问清需求：堂食/外带、杯型、是否含咖啡因；
2. 用知识库检索菜单与活动，再作推荐，禁止凭记忆编造商品；
3. 顾客确认后，输出订单摘要：商品、杯型、数量、预计取餐时间。

# 能力边界
- 涉及退款、投诉、发票，一律回复转人工电话 400-xxx-xxxx；
- 菜单上没有的商品，直接说明"暂未上架"，不要虚构；
- 不回答与点单无关的话题，礼貌引导回正题。

# 输出格式
- 全文口语化，单次不超过 120 字，不使用表格；
- 推荐时最多给 2 个选项，并说明推荐理由。

示例二是知识库文档整理时的分段对照，说明好坏差异：

❌ 差的分段（机械按字数硬切，语义被截断）：
"……拿铁使用双份浓缩，奶泡厚度约 1 厘米，口感绵密，适合搭配甜点；焦糖玛"
（下一段开头是"奇朵……"）

✅ 好的分段（按语义切分，每段自带标题与关键词）：
【商品：拿铁】双份浓缩 + 蒸奶，奶泡约 1cm，口感绵密，推荐搭配曲奇。
关键词：拿铁 latte 含咖啡因 热饮 冷饮
【商品：焦糖玛奇朵】浓缩 + 蒸奶 + 焦糖淋酱，甜度较高。
关键词：玛奇朵 macchiato 甜 含咖啡因
💡 提示：每段自带标题与关键词，检索命中率会明显提升——这相当于给向量检索加了"路标"。

四、实践任务

  1. 任务 1：在 Coze 创建一个新 Bot，按五块骨架写好人设提示词，在预览框里验证角色是否稳定。
  2. 任务 2：上传一份你熟悉的资料（产品说明/规章制度）到知识库，用 5 个真实问题做命中测试并记录命中率。
  3. 任务 3：设计 3 个越界问题（要折扣、要转人工、编造商品），验证边界条款是否生效，据此修改提示词。
  4. 任务 4（进阶，可选）：给智能体挂载一个插件（如天气或搜索），让它在需要时调用，并观察日志中的调用轨迹。

六、自检清单

  • 我能画出智能体四要素（模型/提示词/知识库/工具）的关系图吗？
  • 我的提示词是否包含角色、边界、流程、格式、语气五块内容？
  • 我上传知识库后是否做过真实问题的命中测试并据此优化分段？
  • 我能否用调试日志说清一次回答"为什么是这个结果"？
