LCEL 声明式链路编排

预计 1 天模块四 · LangChain

一、学习目标

  • 能够解释 LCEL（LangChain Expression Language）声明式编排相比手写命令式代码的优势。
  • 能够读懂由 | 组成的多段管道，说明每一段的输入输出类型如何衔接。
  • 能够使用 RunnableParallel、RunnableLambda、RunnablePassthrough 构建分支与并行结构。
  • 能够为链路加上 流式输出、批处理、重试与降级（fallbacks），并把一个 RAG 系统完整改写成 LCEL。

二、核心知识点

知识点 1：LCEL 是什么，为什么用它

LCEL 是 LangChain 的声明式链路编排语法：用 |（管道符）把多个组件串成一条链，例如 prompt | model | parser。它与你手写 resp = model.invoke(prompt.format(...)); return parser.parse(resp) 的区别在于：LCEL 从第一天起就免费获得流式（stream）、批量（batch）、异步（ainvoke）、重试（with_retry）、降级（with_fallbacks）、回调追踪等能力——这些若手工实现，每一项都要写几十行胶水代码。

被组合的每个组件都实现了统一的 Runnable 接口，暴露同名方法：invoke（单次）、batch（批量）、stream（流式）、astream（异步流式）。因此"整条链"和"链里的一步"用法完全一致，可以随意嵌套组合。

知识点 2：组合原语与类型衔接规则

① 管道 |：前一步输出作为后一步输入，核心规则是类型必须衔接（如 prompt 输出 ChatPromptValue，正好是 model 的输入）；② RunnableParallel：同一份输入分发给多个分支并行执行，输出一个字典——典型用法是"一份输入同时做检索和改写"；③ RunnableLambda：把普通函数（含 lambda）包成 Runnable，用于格式化、后处理等胶水逻辑；④ RunnablePassthrough：原样透传输入，常用于"字典里只替换一个键、其余保留"的场景；⑤ RunnableBranch：按条件走不同分支。当管道某段接收"字典"输入时，字典的每个键会各自独立地流经对应分支——这是 RAG 链最常用的写法（一边检索、一边透传问题）。

知识点 3：生产级能力——流式、重试与降级

流式：对链调用 .stream() 即可逐 token 拿到输出，配合前端打字机效果，把"首字延迟"从十几秒降到几百毫秒，是 LLM 应用体验的分水岭。重试：chain.with_retry(stop_after_attempt=3) 自动对限流/超时做指数退避。降级：chain.with_fallbacks([backup_chain])——主模型挂了自动切备用模型（如 gpt-4o → gpt-4o-mini → 本地模型），是可用性的关键保险。此外 model.bind(temperature=0, max_tokens=500) 可在不改模板的情况下给模型绑定额外参数。

知识点 4：从 LLMChain 到 LCEL 的迁移思路

旧式 LLMChain(llm, prompt, memory) 的三要素在 LCEL 中一一对应：prompt | llm | parser；memory 则由上一节的 RunnableWithMessageHistory 接管。迁移口诀："链改管道、内存改历史、回调改 config"。写好一条 RAG 管道后，它既是 API 服务的 handler，也能直接被 Agent 当作工具调用（@tool 里 invoke 链即可），复用性极高。

三、示例演示

示例一：用 LCEL 重写一个完整的 RAG 管道——检索、格式化、生成、引用一步到位：

# pip install langchain langchain-openai langchain-chroma
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_chroma import Chroma

retriever = Chroma(persist_directory="./chroma_demo",
                   collection_name="kb_demo",
                   embedding_function=OpenAIEmbeddings()).as_retriever(search_kwargs={"k": 4})

prompt = ChatPromptTemplate.from_template(
    "仅根据以下资料回答问题，答案末尾用[来源]标注引用的页码；"
    "资料不足时回答'未找到相关信息'。\n\n资料：\n{context}\n\n问题：{question}"
)

def format_docs(docs):
    return "\n\n".join(f"[第{d.metadata.get('page', '?')}页] {d.page_content}" for d in docs)

rag_chain = (
    # 字典的两个键各自走一条分支：context 由检索器产出，question 原样透传
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt
    | ChatOpenAI(model="gpt-4o-mini", temperature=0)
    | StrOutputParser()
)

# 流式输出：边生成边返回，首字延迟大幅下降
for token in rag_chain.stream("发票可以开增值税专用发票吗？"):
    print(token, end="", flush=True)

示例二：并行分支 + 普通函数 + 重试与降级，组合出一条生产可用的链：

from langchain_core.runnables import RunnableParallel, RunnableLambda

# 同一份输入并行跑两路：关键词抽取（本地函数）与模型摘要
pipeline = RunnableParallel(
    keywords=RunnableLambda(lambda q: [w for w in q.split() if len(w) >= 2][:5]),
    summary=(prompt | model | StrOutputParser()),
)

safe = (prompt | model | StrOutputParser()) \
    .with_retry(stop_after_attempt=3) \
    .with_fallbacks([prompt | backup_model | StrOutputParser()])

result = pipeline.invoke("帮我总结一下这个季度的销售数据")
print(result["keywords"], result["summary"][:80])
# 批量：10 个问题一次并发处理
answers = safe.batch(["问题A", "问题B", "问题C"])
💡 提示：调试 LCEL 链时，用 chain.get_graph().print_ascii() 可以直接打印链路结构图；配合 config={"run_name": "my-rag"} 在 LangSmith 里追踪每一步耗时与输入输出。

四、实践任务

  1. 任务 1：把模块三完成的 RAG 系统改写成示例一那样的 LCEL 单链，要求带"资料不足拒答"与来源标注，并用 stream 输出。
