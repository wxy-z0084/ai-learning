训练数据收集、清洗与格式构造

预计 1.5 天模块二 · LoRA 微调

一、学习目标

  • 能够从业务日志、专家标注、合成数据、公开数据集四类来源规划训练数据，并说明合规边界。
  • 能够完成去重、质量过滤、脱敏、长度均衡四步清洗，量化清洗前后的数据变化。
  • 能够把原始样本转成 Alpaca / ShareGPT 标准格式，并正确注册进 LLaMA-Factory 的 dataset_info.json。
  • 能够划分训练/验证/测试三份数据并防止泄漏，给数据集建立版本号。

二、核心知识点

知识点 1：四类数据来源与取舍

① 业务日志：工单与处理结果、人工修订的草稿、审核记录——最真实、免费，但要先脱敏（手机号、身份证、订单金额等 PII 必须掩码）并确认劳动成果的使用授权。② 专家标注：质量最高、可定制格式，成本也最高；用小批量先行：先标 100 条看模型收益，值得再扩到上千条。③ 合成数据：用强模型批量生成"输入→输出"再人工抽检，能把 100 条扩成 5000 条；风险是引入强模型的口癖与错误，务必混入真实数据且比例不超过一半。④ 公开数据集：补通用能力、防灾难性遗忘，但要核对许可证（是否允许商用与二次分发）。经验法则：数据质量 > 数据数量，3000 条干净样本通常胜过 5 万条噪声。

知识点 2：清洗四步

① 去重：先精确去重（归一化后哈希），再模糊去重（MinHash/SimHash 或 embedding 相似度 > 0.95 合并）——重复样本会放大少数模式，导致模型过拟合到高频句式。② 质量过滤：剔除过短（输出不足 10 字）、过长（远超窗口）、乱码、答案含"我不知道"占位、标签明显错误的样本；抽样人读 50 条定过滤规则。③ 脱敏与合规：正则掩码手机号/证件号/邮箱，删除业务敏感字段，保留一份"原始→脱敏"对照以便审计。④ 长度与类别均衡：各分类样本量差距不要超过 10 倍，否则模型会偏向多数类；输入输出长度分布要接近真实线上流量。清洗要写成脚本而不是手工操作，报告里保留"清洗前 N 条 → 清洗后 M 条，各规则删了多少"。

知识点 3：格式构造与切分

主流两种格式：Alpaca（单轮：instruction / input / output）适合分类、抽取等单轮任务；ShareGPT（多轮：conversations 列表，role 为 human/gpt 交替）适合对话与多轮改写。字段对齐要准确——instruction 是任务指令，input 是待处理内容，别把问题塞进 instruction 造成两列语义混乱。数据切分常用 90/5/5 或 8/1/1，测试集只在最终验收时碰一次；同一业务实体的多条记录必须落在同一侧（同一工单的两次修改不能一半训练一半测试），否则指标虚高。最后给数据集打版本号并记录生成脚本 commit，微调实验的可复现性从这里开始。

三、示例演示

示例一：清洗 + 格式转换 + 切分的一体化脚本（Python）。输入 raw.jsonl 每行含 question/answer/category，输出 Alpaca 格式的训练集与验证集：

import json, hashlib, re, random

random.seed(42)
PII = [(re.compile(r"1[3-9]\d{9}"), "****手机****"),
       (re.compile(r"\d{17}[\dXx]"), "****证件****")]

def clean(text: str) -> str:
    text = re.sub(r"\s+", " ", text).strip()
    for pattern, mask in PII:
        text = pattern.sub(mask, text)
    return text

def build(raw_path: str):
    seen, rows, report = set(), [], {"dup": 0, "too_short": 0, "keep": 0}
    for line in open(raw_path, encoding="utf-8"):
        r = json.loads(line)
        q, a = clean(r["question"]), clean(r["answer"])
        if len(a) < 10:                      # 输出过短：模型学不到东西
            report["too_short"] += 1
            continue
        key = hashlib.md5((q + "||" + a).encode()).hexdigest()
        if key in seen:                       # 精确去重
            report["dup"] += 1
            continue
        seen.add(key)
        rows.append({"instruction": f"对下面的工单分类并输出 60 字内摘要，类别从"
                                    f"物流/退款/质量/账号中选择。\n工单：{q}",
                     "input": "",
                     "output": json.dumps({"category": r["category"], "summary": a},
                                          ensure_ascii=False)})
        report["keep"] += 1

    random.shuffle(rows)
    cut = int(len(rows) * 0.9)
    json.dump(rows[:cut], open("train.json", "w", encoding="utf-8"), ensure_ascii=False, indent=2)
    json.dump(rows[cut:], open("valid.json", "w", encoding="utf-8"), ensure_ascii=False, indent=2)
    print(f"清洗报告：{report}  训练 {cut} / 验证 {len(rows) - cut}")

if __name__ == "__main__":
    build("raw.jsonl")

{

四、实践任务

  1. 任务 1：盘点手头可用数据源，列出每个来源的条数、格式、是否有 PII、是否需授权，产出一页数据来源清单。
  2. 任务 2：编写清洗脚本，实现脱敏、归一化去重、长度过滤、类别统计，跑通并输出"清洗前 N → 清洗后 M"的规则级报告。
  3. 任务 3：把清洗后的数据转成 Alpaca 或 ShareGPT 格式（300 条以上），按 9:1 切分，写好 dataset_info.json 并在 LLaMA-Factory 中确认能被识别。
  4. 任务 4（进阶，可选）：用强模型合成 200 条边界样本，人工抽检标注合格率；统计合成数据占比并控制在 50% 以内，说明混入目的。

五、推荐资源

  • 📖 Hugging Face Datasets 官方文档 — 数据加载、map/clean、切分的标准工具，清洗脚本可逐步迁移到它上面。
  • 📖 Datasets：Processing data — 去重、映射、抽样与 train_test_split 的官方教程，对应本节清洗与切分。
  • 📖 Stanford Alpaca — Alpaca 格式的原始出处，含其数据生成方法，可借鉴做合成数据。
  • 📖 LLaMA-Factory 数据说明 — dataset_info.json 字段与支持格式的权威文档，注册数据集前对照它的示例。
  • 🛠 Label Studio — 开源标注工具，需要专家标注时用它组织小批量标注与复核。

六、自检清单

  • 我能说出四类数据来源各自的成本、质量与合规风险吗？
  • 我的清洗有可复现的脚本和规则级统计报告，而不是只靠手工删吗？
  • 我的训练/验证/测试三份数据按实体隔离、无泄漏，并打了版本号吗？
  • 我的数据集已注册进 dataset_info.json，能被 LLaMA-Factory 正确读取吗？
