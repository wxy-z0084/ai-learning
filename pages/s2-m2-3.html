接口鉴权（JWT / OAuth2）

预计 0.5 天模块二 · FastAPI

一、学习目标

  • 能够区分认证（Authentication）与授权（Authorization），说清 401 与 403 的差别。
  • 能够解释 OAuth2 密码模式与授权码模式的适用场景，以及访问令牌与刷新令牌的分工。
  • 能够手写 JWT 的签发与校验流程（含过期时间与签名算法），并设计成可复用依赖。
  • 能够列出令牌安全的常见红线：密钥保管、HTTPS、过期时长、密码哈希与刷新令牌轮换。

二、核心知识点

知识点 1：认证与授权，以及 OAuth2 的定位

认证回答「你是谁」，授权回答「你能做什么」。HTTP 语义：未提供凭证返回 401 Unauthorized，凭证有效但权限不足返回 403 Forbidden。OAuth2（RFC 6749）本质是一个授权协议，定义了授权码、密码、客户端凭证、隐式等模式；在前后端 API 项目里最常用的是密码模式（Resource Owner Password Credentials）：客户端提交用户名密码 → 服务器换发令牌，之后所有请求只带令牌。第三方登录（微信/GitHub 授权）则必须用授权码模式，你的服务永远拿不到用户在第三方的密码。注意 OAuth2 本身不规定令牌格式，实践中普遍搭配 JWT 作为令牌载体。

知识点 2：JWT 的结构与校验

JWT（JSON Web Token, RFC 7519）由三段 Base64Url 组成：header.payload.signature。头部声明算法（如 HS256）；载荷是声明集合——sub（主体 id）、exp（过期时间）、iat（签发时间）、role 等业务声明；签名用服务端持有的密钥对前两段做 HMAC/摘要，防篡改。关键特性：签名只保证完整性，不保证机密性——payload 只是编码不是加密，任何人都能解码看到内容，所以绝不能把密码、密钥写进 JWT。校验三件事：签名是否有效（防伪造/防改内容）、exp 是否过期、iss/aud 是否符合预期。

有状态 vs 无状态：JWT 校验只需本地计算，无需查库，天然横向扩展；代价是签发后无法单方面作废（直到过期），因此实践上把访问令牌有效期设短（15~30 分钟），配合刷新令牌（数天、存 httpOnly Cookie 或服务端记录）换取新访问令牌，并在需要强制下线时将刷新令牌入库拉黑/轮换。

知识点 3：FastAPI 落地姿势

标准结构：登录接口接收 OAuth2PasswordBearer 定义的表单（username/password），比对哈希后的密码（passlib/bcrypt，严禁明文或裸 MD5），用 python-jose/PyJWT 签发含 exp 的 access_token；受保护路由声明 token: str = Depends(oauth2_scheme)，再由 get_current_user 依赖解码校验并查库取用户，校验失败抛 401。OAuth2 规范要求密码模式用 application/x-www-form-urlencoded 提交（curl -d "username=..&password=.."），/docs 会显示授权按钮。更细粒度的 Scope 可表达「读/写」权限，FastAPI 的 Security(..., scopes=[...]) 提供原生支持。

知识点 4：安全红线清单

① 密钥放环境变量并定期轮换，长度足够（HS256 建议 ≥32 字节随机串），严禁硬编码进 git；② 算法在服务端白名单固定，绝不能信任 token 头部自带的 alg（历史上 none 算法伪造漏洞正源于此）；③ 传输强制 HTTPS；④ 密码必须加盐哈希存储；⑤ 刷新令牌一次性轮换、检测重放；⑥ 日志与错误信息里不打印令牌全文；⑦ 令牌之外还要做接口级授权检查——「拿到合法 token」不等于「能访问别人的数据」，按资源归属做二次校验（IDOR 防护）。

三、示例演示

示例一：完整的密码模式登录 + JWT 签发与校验依赖（依赖包：pip install "fastapi[standard]" python-jose[cryptography] passlib[bcrypt]）：

from datetime import datetime, timedelta, timezone
from fastapi import Depends, FastAPI, HTTPException, status
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
from jose import JWTError, jwt
from passlib.context import CryptContext

SECRET_KEY = "请替换为环境变量中的32字节以上随机串"
ALGORITHM = "HS256"
ACCESS_TOKEN_EXPIRE_MIN = 30

app = FastAPI()
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")  # /docs 按钮指向这里

# 模拟用户库：真实项目从数据库读取
USERS = {"alice": {"id": 1, "hashed": pwd_context.hash("secret123"),
                   "role": "admin"}}

def verify_password(plain: str, hashed: str) -> bool:
    return pwd_context.verify(plain, hashed)

def create_access_token(sub: str, role: str) -> str:
    payload = {"sub": sub, "role": role,
               "exp": datetime.now(timezone.utc)
                      + timedelta(minutes=ACCESS_TOKEN_EXPIRE_MIN)}
    return jwt.encode(payload, SECRET_KEY, algorithm=ALGORITHM)

@app.post("/token")
def login(form: OAuth2PasswordRequestForm = Depends()):
    user = USERS.get(form.username)
    if not user or not verify_password(form.password, user["hashed"]):
        raise HTTPException(status.HTTP_401_UNAUTHORIZED,
                            detail="用户名或密码错误",
                            headers={"WWW-Authenticate": "Bearer"})
    return {"access_token": create_access_token(form.username,
                                                user["role"]),
            "token_type": "bearer"}

def get_current_user(token: str = Depends(oauth2_scheme)) -> dict:
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username = payload.get("sub")
        if username is None or username not in USERS:
            raise JWTError("无效主体")
    except JWTError:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED,
                            detail="凭证无效或已过期",
                            headers={"WWW-Authenticate": "Bearer"})
    return {"username": username, "role": payload["role"]}

@app.get("/me")
def me(user: dict = Depends(get_current_user)):
    return user

示例二：调用方式（先换令牌，再带令牌访问受保护接口）：

# 1. 换取令牌（OAuth2 密码模式要求表单编码）
curl -X POST http://127.0.0.1:8000/token \
  -d "username=alice&password=secret123"

# 返回：{"access_token": "eyJhbGciOi...", "token_type": "bearer"}

# 2. 携带令牌访问
curl http://127.0.0.1:8000/me \
  -H "Authorization: Bearer eyJhbGciOi..."

# 3. 不带/带错令牌 → 401；令牌有效但访问他人资源 → 403
💡 提示：解码自己的 token 看看：访问 https://jwt.io 可视化解码三段内容，直观理解「payload 不加密只编码」。教学演示可用固定 SECRET_KEY，上线前务必改从环境变量读取。

四、实践任务

  1. 任务 1：实现 /token 登录与 /me 当前用户接口，分别验证：正确凭证 200、错误密码 401、无 Authorization 头 401、篡改 payload 内容后 401。
  2. 任务 2：把令牌过期时间调成 10 秒，等待过期后再请求，确认返回 401；记录响应头中的 WWW-Authenticate 字段。
  3. 任务 3：在 get_current_user 基础上加角色检查依赖，实现 /admin 只允许 role=admin 访问（权限不足返回 403），并写一个校验他人资源归属的路由防止 IDOR。
  4. 任务 4（进阶，可选）：实现刷新令牌方案：/token 返回短效 access_token + 长效 refresh_token（入库记录），/refresh 接口校验后轮换（旧刷新令牌作废），试着重放旧令牌验证被拒绝。
