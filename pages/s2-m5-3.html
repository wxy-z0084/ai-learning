阶段二 · 智能体开发

Docker 容器化与发布流程

预计 1 天模块五 · 企业级开发与部署

一、学习目标

  • 能够读懂并编写 Dockerfile，说明镜像分层原理并写出更小、更安全的镜像。
  • 能够用多阶段构建与 .dockerignore 把 Python 智能体服务打包成可运行镜像。
  • 能够用 docker compose 编排应用与依赖（向量库、Redis），实现一条命令起整套环境。
  • 能够描述"构建 → 打 tag → 推送 → 部署 → 验证 → 回滚"的完整发布流程。

二、核心知识点

知识点 1：镜像与分层——Docker 的底层逻辑

Dockerfile 中每条指令生成一个只读层，层层叠加构成镜像；容器启动时在最上层加一个可写层。分层带来两个直接收益：一是缓存——上层没变就复用下层缓存，构建极快；二是共享——同一台机器的多个镜像共用相同基础层。因此写 Dockerfile 要按"变化频率从低到高"排列指令：先 COPY 依赖清单并安装，再 COPY 源码。反过来写（先拷代码再装依赖），每次改一行代码都会重装全部依赖。

常见坑：使用 latest 标签导致环境不可复现（务必固定 python:3.12-slim 这类具体版本）；以 root 运行应用（应创建非 root 用户）；在镜像里塞入 .env 与日志（应通过 .dockerignore 排除、运行时注入）。

知识点 2：多阶段构建与镜像瘦身

Python 项目常需要编译依赖（如某些向量库、grpc），构建工具链会让镜像膨胀数 GB。多阶段构建用两个 FROM：第一阶段（builder）安装依赖并编译，第二阶段（runtime）只从 builder COPY 产物，构建工具不会进入最终镜像。配合 python:3.12-slim 基础镜像、--no-cache-dir、.dockerignore，一个 FastAPI 智能体服务镜像通常能控制在几百 MB 以内。体积小还意味着更小的攻击面与更快的拉取速度。

知识点 3：Compose 编排与发布流程

开发与联调阶段用 docker-compose.yml 一次性拉起"应用 + Qdrant/Chroma + Redis"，团队成员不需要各自安装依赖，环境完全一致。生产发布则是流水线：CI 里执行 docker build 打上 版本号 tag（如 git commit 短哈希）→ docker push 推到镜像仓库（Harbor/ACR/Docker Hub）→ 部署平台（K8s、云主机 systemd）拉取指定 tag 启动 → 健康检查通过后切流 → 异常时回滚到上一个 tag，因为旧镜像仍在仓库中，回滚成本极低。关键点：镜像 tag 必须与代码版本一一对应，绝不允许"构建后覆盖同一 tag"。

三、示例演示

示例一：智能体服务的多阶段 Dockerfile：

# ---------- Dockerfile ----------
FROM python:3.12-slim AS builder
WORKDIR /build
COPY pyproject.toml README.md ./
COPY src ./src
RUN pip install --no-cache-dir --prefix=/install .

FROM python:3.12-slim
RUN useradd --create-home --uid 1000 appuser
WORKDIR /app
COPY --from=builder /install /usr/local
COPY src ./src
COPY configs ./configs
USER appuser
EXPOSE 8000
CMD ["uvicorn", "src.agent_hub.main:app", "--host", "0.0.0.0", "--port", "8000"]

配套的 .dockerignore 与 compose 文件（应用 + 向量库）：

# ---------- .dockerignore ----------
.git
.venv
.env
logs/
data/
tests/
__pycache__/
*.md

# ---------- docker-compose.yml ----------
services:
  kb-agent:
    build: .
    image: registry.example.com/kb-agent:${TAG:-dev}
    env_file: .env
    restart: unless-stopped
    ports:
      - "8000:8000"
    depends_on:
      - qdrant

  qdrant:
    image: qdrant/qdrant:v1.12.1
    volumes:
      - qdrant_data:/qdrant/storage

volumes:
  qdrant_data:
💡 提示：本地开发用 docker compose up --build 一键启动；发布用 docker build -t registry.example.com/kb-agent:$GIT_SHA . && docker push … 把 commit 哈希写进 tag，出问题时能精确回滚到任意历史版本。

四、实践任务

  1. 任务 1：为 s2-m5-1 中的 kb-agent 项目编写 Dockerfile，构建后用 docker run --env-file .env -p 8000:8000 启动，curl 健康检查接口通过。
  2. 任务 2：用 docker images 记录优化前镜像体积，加入多阶段构建与 .dockerignore 后再对比，目标体积下降 30% 以上。
  3. 任务 3：编写 docker-compose.yml，把应用与向量库编排起来，验证 compose down 再 up 后向量数据仍在（volume 持久化）。
  4. 任务 4（进阶，可选）：在本地 registry（如 docker run -p 5000:5000 registry:2）演练"构建 v1 → 推送 → 改代码构建 v2 → 回滚 v1"的完整流程。
