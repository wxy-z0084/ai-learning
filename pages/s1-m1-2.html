阶段一 · 指挥AI写软件

Bot 创建与人设配置

预计 0.5 天模块一 · Coze 平台使用

一、学习目标

  • 能够从零创建一个扣子 Bot，并选择合适的底层模型与参数配置。
  • 能够写出结构完整的人设与回复逻辑（Persona Prompt），包含角色、能力边界、语气与拒答策略。
  • 能够使用开场白、建议问题、语音等 UI 元素提升 Bot 的首轮体验。
  • 能够通过预览与调试区域定位人设问题，并完成一次有效迭代。

二、核心知识点

知识点 1：创建 Bot 与选择模型

进入工作区后点击「创建 Bot」，需要填写名称、功能介绍、图标三项基本信息。名称会展示给最终用户，建议「动词 + 对象」式命名（如「周报小助手」）而不是抽象名词；功能介绍既给人看也给模型做上下文参考。创建后进入编辑页，左侧是编排（人设与插件/工作流），中间是预览与调试，右侧是体验与发布，这个三栏布局是扣子的核心工作台。

模型选择上，扣子国内版提供云雀（L Doubao 系列）、DeepSeek 等多种模型，通常可按 模型代号（如 doubao-pro、deepseek-v3）选择，并调节温度（temperature）与回复长度上限。经验法则：客服、事实问答类用低温度（0.1~0.3）保证稳定；创意写作类用高温度（0.7~1.0）。温度调高会放大幻觉，配合知识库使用时优先低温度。

知识点 2：人设与回复逻辑（Persona Prompt）

「人设与回复逻辑」输入框就是这个 Bot 的系统提示词，是整个 Bot 的大脑。一份好的人设至少包含四段：①角色定位（你是谁、为谁服务）；②能力范围（能做什么，最好逐条列出）；③行为约束（不能做什么、遇到超纲问题怎么回答、用什么语气）；④输出格式（要不要用 Markdown、要不要分点）。扣子在输入框上方提供「优化」按钮，可让大模型帮你把口语化描述改写成结构化提示词，但优化结果必须人工审校，防止它引入你不想要的能力。

常见坑：把人设写成一句话（「你是一个客服」），导致行为随机；或者人设里塞入大量业务数据——数据应该放进知识库，人设只放「怎么用这些数据」的规则，否则每次改数据都要改提示词、触发版本混乱。

知识点 3：开场白、建议问题与调试区

编排页下方的「开场白文案」支持纯文本或图文卡片，用于向用户说明 Bot 能做什么；开场白预置问题（建议问题）可配置 3~4 个按钮，直接引导用户问出你最希望被触发的意图，这对冷启动期的体验至关重要。中间调试区每轮对话会显示模型输出与插件/工作流调用轨迹，人设没生效、工具没被触发，都在这里一眼看出来。调试满意后再点右上角「发布」，未发布的修改只对自己可见。

三、示例演示

下面是一份可直接粘贴进「人设与回复逻辑」框的完整示例：一个面向公司内部的「报销政策问答助手」。注意四段式结构与占位内容的具体化写法：

# 角色
你是「财务小助手」，服务于公司全体员工，帮助他们快速了解差旅与日常费用报销政策。

# 能力范围
1. 解释报销标准：差旅住宿、交通、餐补的具体金额与城市分级。
2. 说明报销流程：填单 → 审批 → 打款的各环节与时限。
3. 判断单据是否合规：根据政策指出缺少的发票类型或超标项。

# 行为约束
- 只回答与公司报销政策相关的问题；其他话题礼貌拒绝并引导回报销场景。
- 当政策知识库中查不到具体金额时，明确说「建议咨询财务同事」，禁止编造数字。
- 语气专业、简洁，称呼用户为「您」，单次回答不超过 200 字。

# 输出格式
默认用 Markdown 分点作答；涉及金额时使用表格对比城市级别。

粘贴后在右侧调试区试三个问题：「去上海出差住酒店能报多少？」、「帮我写一首诗」（应被拒绝）、「发票丢了怎么办」（应引导咨询人工）。观察拒绝话术是否自然、是否遵守 200 字限制，不满足就回去改约束段落。

💡 提示：调试时打开「显示回复来源/调试信息」，可以看到模型每轮实际收到的系统提示词长度与知识库命中情况，人设「看起来没生效」时先查这里，八成是提示词被截断或被用户消息带偏。

四、实践任务

  1. 任务 1：创建一个「周报撰写助手」Bot，人设按四段式写完整，选 deepseek 或豆包低温度模型，写完后用「优化」按钮对比机器改写版与你的版本差异，吸收其优点后合并。
  2. 任务 2：为该 Bot 配置开场白文案和 3 条建议问题，验证点击建议问题能触发符合预期的回答。
  3. 任务 3：设计 3 个「应该被拒绝」的越界问题（如写代码、聊八卦），在调试区验证拒绝话术一致且不生硬；再设计 3 个正常问题验证能力覆盖。
  4. 任务 4（进阶，可选）：把温度从 0.3 调到 1.0，用同一个问题连问 5 次，记录回答稳定性的变化，写一段 100 字的观察结论。

六、自检清单

  • 我能不看笔记写出人设四段式（角色/能力/约束/格式）的框架吗？
  • 我知道温度参数调高调低分别适合什么场景、有什么副作用吗？
  • 当 Bot 行为异常时，我知道先去调试区看哪三样信息吗？
  • 我能解释为什么业务数据不该写进人设框吗？
