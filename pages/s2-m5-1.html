阶段二 · 智能体开发

智能体工程化目录与配置管理

预计 0.5 天模块五 · 企业级开发与部署

一、学习目标

  • 能够把一个"单文件脚本"形态的智能体重构为标准 Python 工程目录，说明每个目录的职责。
  • 能够使用 pydantic-settings 实现"代码默认值 + .env 环境变量 + 配置文件"三层配置，并区分哪些内容绝不入库。
  • 能够用 pyproject.toml 声明依赖，做到换一台机器也能一条命令复现运行环境。
  • 能够自查现有项目的配置风险（硬编码密钥、环境不一致、路径写死）并给出整改清单。

二、核心知识点

知识点 1：从脚本到工程——标准目录布局

原型阶段常把所有代码写进一个 notebook 或 agent.py，一旦要接入监控、多人协作、Docker 部署，问题立刻暴露：模块互相 import 混乱、配置散落各处、日志与数据文件混在代码目录里。工程化的核心动作是按职责拆目录：业务代码放进 src 布局（src/agent_hub/），配置声明放进 pyproject.toml，环境差异放进 configs/ 与 .env，可运行入口固定为 main.py 或 cli.py，测试、脚本、日志各归各位。

常见坑有两个：一是把 .env、密钥、向量库数据提交进 Git（应用 .gitignore 明确排除，并保留 .env.example 作为模板）；二是用 sys.path.append 之类的方式 hack 导入路径，应改为 pip install -e . 安装自身包，让导入路径由包管理决定。

知识点 2：配置分层与类型校验

企业项目里配置通常分三层：代码内默认值（最稳定的行为）、配置文件（按 dev/test/prod 切换）、环境变量（容器与 CI 中注入，优先级最高）。用 pydantic-settings 的 BaseSettings 可以一次读取 .env 与环境变量，并自动做类型转换与必填校验——缺少 API Key 时程序在启动阶段就报错，而不是等到调用模型时才失败。

实践要点：通过 @lru_cache 缓存 get_settings()，避免每个模块重复读文件；密钥类字段用 SecretStr，打印日志时自动脱敏；所有超时、重试次数、模型名都走配置，不要散落魔法数字。

知识点 3：依赖与可复现环境

把直接依赖写进 pyproject.toml 的 dependencies，团队统一用同一个安装方式（pip、uv 均可），避免"我电脑上能跑"。原则：锁文件或版本下界要进版本库，虚拟环境 .venv/ 不进版本库。遵循 12-Factor 应用的"把配置存环境"与"严格分离构建与运行阶段"，后续 Docker 化会顺畅很多。

三、示例演示

先看推荐的目录骨架（以知识库智能体为例），再看配置类写法：

kb-agent/
├── pyproject.toml        # 依赖与项目元信息（进 Git）
├── .env.example          # 环境变量模板（进 Git，无真实密钥）
├── .gitignore            # 排除 .env / .venv / logs / data
├── configs/
│   ├── dev.yaml
│   └── prod.yaml
├── src/agent_hub/
│   ├── __init__.py
│   ├── config.py         # 配置模型（唯一读取 .env 的地方）
│   ├── llm/              # 模型调用封装
│   ├── tools/            # 工具函数
│   └── main.py           # FastAPI / CLI 入口
├── tests/
├── scripts/              # 迁移、索引重建等运维脚本
└── logs/

配置类：启动时完成类型校验，任何模块都通过 get_settings() 获取配置，不直接碰 os.environ。

# src/agent_hub/config.py
from functools import lru_cache
from pydantic import SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env", env_file_encoding="utf-8", extra="ignore"
    )

    app_name: str = "kb-agent"
    env: str = "dev"
    llm_api_key: SecretStr
    llm_base_url: str = "https://api.deepseek.com"
    llm_model: str = "deepseek-chat"
    max_retries: int = 3
    request_timeout: float = 30.0
    log_level: str = "INFO"


@lru_cache
def get_settings() -> Settings:
    return Settings()


if __name__ == "__main__":
    s = get_settings()
    print(s.app_name, s.env, s.llm_api_key)  # SecretStr 打印为 masked
💡 提示：把 llm_api_key 这类敏感项写进 .env 并在 .gitignore 中排除，仓库里只保留 .env.example（写出变量名和示例值）。上线时改用部署平台的密钥管理，而不是把 .env 打进镜像。

四、实践任务

  1. 任务 1：把你之前写的任一智能体脚本拆成本页的目录结构，入口改为 python -m agent_hub.main 可运行。
  2. 任务 2：用 pydantic-settings 重写配置读取，删除代码中所有 os.environ 与硬编码密钥；提交 .env.example 与 .gitignore。
  3. 任务 3：编写 pyproject.toml 声明依赖，在全新虚拟环境中执行 pip install -e . 后能直接跑通入口与 pytest。
  4. 任务 4（进阶，可选）：为 dev/prod 各写一份 configs yaml，通过环境变量 APP_ENV 切换，并验证缺密钥时启动立即失败。

  • 📖 The Twelve-Factor App 中文版 — 企业应用配置与部署的十二条原则，半天读完，工程化决策的判断标尺。
  • 📖 PyPA 官方打包指南 — pyproject.toml、可编辑安装与虚拟环境的权威说明。
