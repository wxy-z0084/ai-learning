阶段二 · 智能体开发

实战：企业知识库问答智能体

预计 1.5 天模块五 · 企业级开发与部署

一、学习目标

  • 能够独立搭建一套 RAG 知识库问答服务：文档加载、切分、向量化、检索、生成全流程。
  • 能够针对企业文档特点选择合理的切分策略与检索参数，并解释其对效果的影响。
  • 能够通过引用溯源、拒答策略与评测集控制幻觉、量化回答质量。
  • 能够把该服务按模块五的工程规范（配置、日志、限流、Docker）打包为可部署的生产级应用。

二、核心知识点

知识点 1：RAG 全流程拆解

RAG（检索增强生成）解决大模型不知道"你公司内部的事"以及会编造的问题。流程分离线与在线两段：离线索引——加载文档（PDF/Word/Markdown）→ 切分成 chunk → 用 embedding 模型转成向量 → 写入向量库；在线问答——把用户问题转向量 → 在向量库检索 top-k 相关 chunk → 拼进提示词 → 模型生成带引用的答案。相比微调，RAG 更新知识只需重建索引、成本低、可溯源，是企业问答的默认方案。

切分是效果的隐形开关：chunk 太大会稀释相关性并浪费上下文，太小会切断语义。常用 300-800 字符、带 10-20% 重叠，并保留标题层级（把标题路径拼进 chunk 元数据）；对制度类文档按条款切，对 FAQ 按问答对切。

知识点 2：检索质量与提示词设计

默认的向量检索常有短板：口语化问题与书面文档用词不匹配。改进手段包括混合检索（向量 + BM25 关键词）、元数据过滤（限定部门、生效日期）、重排序（用 rerank 模型对 top-20 精排出 top-4）。提示词侧要做三件事：明确角色与边界（仅依据资料回答，资料不足就说不知道）、要求输出引用编号、要求答案结构化（结论 + 依据 + 建议动作）。

知识点 3：评测、幻觉控制与上线

改 prompt 或换模型后不能凭感觉，要建一个 golden 集：30-50 个真实问题 + 标准答案要点，自动统计检索命中率（正确文档是否进 top-k）与答案要点覆盖率，区分"检索问题"与"生成问题"。幻觉控制组合拳：提示词约束 + 强制引用 + 答案后置校验（检查引用编号是否真实存在于检索结果中）+ 高风险问题拒答。上线时结合模块五所学：FastAPI 暴露接口、JSON 日志记录 question/topk/trace_id、令牌桶限流、Docker 部署。

三、示例演示

示例一：离线索引（切分 + 入库）：

# scripts/build_index.py
from langchain_community.document_loaders import DirectoryLoader, TextLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings

loader = DirectoryLoader("./docs", glob="**/*.md", loader_cls=TextLoader)
docs = loader.load()

splitter = RecursiveCharacterTextSplitter(
    chunk_size=600, chunk_overlap=100,
    separators=["\n## ", "\n### ", "\n", "。"]
)
chunks = splitter.split_documents(docs)

vectorstore = Chroma.from_documents(
    chunks,
    embedding=OpenAIEmbeddings(model="text-embedding-3-small"),
    persist_directory="./data/chroma",
)
print(f"入库完成：{len(chunks)} 个片段，来源 {len(docs)} 篇文档")

示例二：在线问答（检索 + 带引用生成）：

# src/agent_hub/rag.py
from langchain_chroma import Chroma
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI, OpenAIEmbeddings

retriever = Chroma(
    persist_directory="./data/chroma",
    embedding_function=OpenAIEmbeddings(model="text-embedding-3-small"),
).as_retriever(search_kwargs={"k": 4})

PROMPT = ChatPromptTemplate.from_template("""你是企业内部知识库问答助手。
规则：
1. 只能依据下面提供的资料回答，禁止编造；
2. 资料不足以回答时，明确回复"资料中未找到"；
3. 答案末尾用 [1][2] 标注引用的资料编号。

资料：
{context}

问题：{question}""")


def answer(question: str) -> str:
    docs = retriever.invoke(question)
    context = "\n\n".join(
        f"[{i + 1}] 来源：{d.metadata.get('source', '未知')}\n{d.page_content}"
        for i, d in enumerate(docs)
    )
    chain = PROMPT | ChatOpenAI(model="deepseek-chat", temperature=0)
    return chain.invoke({"context": context, "question": question}).content
💡 提示：知识库更新不要全量重建——按文档粒度记录内容哈希，变更的文档才重新切分入库；问题先做一次"改写"（补全指代、口语转书面）再检索，命中率通常明显提升。

四、实践任务

  1. 任务 1：准备 10 篇你熟悉领域的 Markdown 文档，完成索引构建，并在不同 chunk_size（300/600/1000）下对比检索命中效果。
  2. 任务 2：实现带引用与拒答策略的问答函数，构造 3 个知识库外的问题，验证模型回答"资料中未找到"而非编造。
  3. 任务 3：编写 20 个问题的评测脚本，输出检索命中率与要点覆盖率两列指标，作为后续迭代基线。
  4. 任务 4（进阶，可选）：用 FastAPI 包装为服务，接入 JSON 日志与令牌桶限流，写出 Dockerfile 完成容器化部署。
