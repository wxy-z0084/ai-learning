升级效果验证与业务价值评估

预计 0.5 天模块一 · 项目集成 AI 能力

一、学习目标

  • 能够构建一份不泄漏、有代表性的评测集，并说明样本从哪来、覆盖哪些类型。
  • 能够为场景选择质量指标 + 效率指标 + 成本指标三类指标并给出量化目标线。
  • 能够用离线评测、人工盲评、线上 A/B 三种手段逐层验证，解释各自能证明什么。
  • 能够把技术指标翻译成业务价值数字（节省工时、错误下降、周期缩短），完成上线汇报。

二、核心知识点

知识点 1：评测集怎么建

评测集是 AI 升级的"考卷"，其质量决定结论可信度。来源：优先取真实历史样本（已有人工处理结果的工单、已归档的合同），补以构造的边界样本（空值、超长、乱码、方言表述、对抗提问）。规模：PoC 阶段 50–100 条即可看出方向，正式验收建议 200 条以上。分层：按类型/渠道/难度分层抽样，避免某一大类霸榜导致"平均分虚高"。防泄漏：评测样本绝不能出现在提示词示例、微调训练集里，否则分数是自欺欺人。评测集要冻结版本（存文件 + 哈希），每次评测用同一份，才可横向对比。

知识点 2：三类指标与目标线

① 质量指标：分类用准确率/F1，抽取用字段级精确率与召回，生成用人工可用率（好/中/差三档）与幻觉率（编造事实的样本占比）。开放式任务无法字符串比对时，用LLM-as-judge：让另一个模型按量表打 1–5 分，但必须先用 30–50 条人工标注校准裁判模型，人工一致率低于 0.7 就别用。② 效率指标：P95 延迟、人工介入率（转人工的占比下降了多少）。③ 成本指标：单次调用成本、日 token 消耗。目标线要写成可判定的形式，如"分类准确率 ≥ 90%、幻觉率 ≤ 2%、P95 ≤ 3s、单次 ≤ 0.01 元"，而不是"效果要好"。

知识点 3：验证的三层与价值换算

三层递进：离线评测（跑冻结评测集，证明基本能力，几小时内完成）→ 人工盲评（新旧方案各占一半、隐藏来源，由业务专家按量表打分，证明"人更愿意用哪个"）→ 线上 A/B（按用户或流量 50/50 分流，观察真实指标，证明业务收益）。价值换算公式：月收益 = 覆盖量 × 单次节省分钟 × 人力分钟成本 + 错误减少 × 单次错误损失，再减去月度模型成本与运维分摊，得到净收益与回本周期。汇报时把"准确率 92%"翻译成"每月少 3 人天返工、回本 2.4 个月"，业务方才买账。上线后还要有持续评测：每周抽样 50 条复跑，监控模型升级或数据漂移引起的退化。

三、示例演示

示例一：一个离线评测脚本（Python），读取评测集 JSONL（每行含输入、期望答案、类型），调用你的 AI 封装并统计准确率、幻觉率、延迟与成本：

import json, time, statistics

PRICE_PER_1K_TOKEN = 0.0008  # 元 / 1K tokens，按实际模型价目表填写

def evaluate(dataset_path: str, predict_fn) -> dict:
    rows = [json.loads(l) for l in open(dataset_path, encoding="utf-8")]
    latencies, correct, hallucination, tokens = [], 0, 0, 0
    by_type: dict = {}

    for row in rows:
        t0 = time.perf_counter()
        out = predict_fn(row["input"])
        latencies.append((time.perf_counter() - t0) * 1000)

        hit = out["answer"] == row["expected"]
        correct += hit
        hallucination += out.get("hallucinated", False)
        tokens += out.get("total_tokens", 0)

        stat = by_type.setdefault(row["type"], [0, 0])
        stat[0] += hit
        stat[1] += 1

    n = len(rows)
    return {
        "样本数": n,
        "准确率": round(correct / n, 3),
        "幻觉率": round(hallucination / n, 3),
        "P95延迟ms": round(statistics.quantiles(latencies, n=20)[-1]),
        "单次成本元": round(PRICE_PER_1K_TOKEN * tokens / n / 1000, 5),
        "分类型准确率": {k: round(v[0] / v[1], 3) for k, v in by_type.items()},
    }

if __name__ == "__main__":
    report = evaluate("eval_set_v1.jsonl", predict_fn=my_predictor)
    print(json.dumps(report, ensure_ascii=False, indent=2))
    # 验收：准确率 ≥ 0.90 且 幻觉率 ≤ 0.02 且 P95 ≤ 3000ms
    ok = report["准确率"] >= 0.90 and report["幻觉率"] <= 0.02 and report["P95延迟ms"] <= 3000
    print("验收结论：", "通过 ✅" if ok else "不通过 ❌，先看分类型准确率定位弱项")

示例二：人工盲评量表（30–50 条即可），新旧方案混排、隐藏来源，评分者只按维度打分：

# blind-review.md —— 人工盲评量表
评分对象：每条结果按 1–5 分打（1=完全不可用，3=改改能用，5=直接可用）
维度：
  1. 事实正确：是否引用真实条款/数据，无编造（编造直接记 1 分并标注）
  2. 格式合规：是否满足 JSON schema 与字数要求
  3. 业务可用：能否免修改直接采纳
输出：每条记录 {样本id, 方案A/B, 三项分, 备注}
汇总：对比两方案的"可用率(≥4分)"与平均分；一致率 = 两人同分条数 / 总条数（目标 ≥ 0.7）
💡 业务价值汇报模板："上线后日均 800 单全部机器首打，人工只处理 12% 置信度不足的单子，等效节省 7.5 人时/天；单日模型成本 23 元 ≈ 140 元人力成本，月净省约 2.6 万元。"

四、实践任务

  1. 任务 1：从历史数据抽样并构造边界样本，建成 50 条以上的评测集 JSONL（含 input、expected、type 三字段），冻结为 v1 并记录行数与哈希。
  2. 任务 2：确定你场景的三类指标与目标线，写进验收标准；跑通示例一的评测脚本，输出首份报告。
  3. 任务 3：做一次 30 条的盲评：新方案与现有做法混排，两人打分，算可用率与一致率，记录最差的 10 条原因。
  4. 任务 4（进阶，可选）：按价值换算公式算出月净收益与回本周期，写 5 行上线汇报（覆盖量、节省、成本、净收益、结论）。

五、推荐资源

  • 📖 Hugging Face Evaluate 文档 — 现成指标库（准确率、F1、ROUGE 等），快速搭起离线评测的第一版。
  • 🛠 promptfoo — 用 YAML 定义用例、批量跑评测并对比多版本提示词，回归测试很实用。
  • 📖 OpenAI Evals 开源库 — 评测集组织方式与用例写法的参考实现，可复用其框架思路。
  • 📖 lm-evaluation-harness — 标准基准评测框架，想与公开榜单对比开源模型时使用。
  • 📖 Microsoft 负责任 AI — 公平性、可靠性评估方法论，做评测维度设计时可借鉴其清单。

六、自检清单

  • 我的评测集有分层、有边界样本、未混入提示词示例或训练数据，并且冻结了版本吗？
  • 我的验收标准是可判定的数字（准确率、幻觉率、延迟、单次成本），而不是"效果良好"吗？
  • 我能说清离线评测、人工盲评、线上 A/B 各自能证明什么、不能证明什么吗？
  • 我能把准确率换算成每月节省的工时与净收益，完成 3 分钟业务汇报吗？
