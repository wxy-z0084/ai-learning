阶段一 · 指挥AI写软件

发布到 Web / 微信 / 飞书等渠道

预计 0.5 天模块一 · Coze 平台使用

一、学习目标

  • 能够完成 Bot 发布流程，理解「草稿版本」与「发布版本」的差别。
  • 能够把 Bot 发布为 Web 链接、嵌入 iframe，并配置开场白等展示参数。
  • 能够完成微信客服、飞书、公众号等渠道的授权接入与验证。
  • 能够通过 API 或 SDK 把已发布 Bot 集成进自有应用，并会做基本的用量监控。

二、核心知识点

知识点 1：发布流程与版本机制

扣子的编辑页里所有修改默认保存为草稿，只有点击右上角「发布」并选择渠道后，才会生成一个正式版本对外生效。这个机制的价值：你可以放心在草稿里做实验，线上用户始终用旧版本；确认无误再一键切新版本。发布前平台会做合规自检：涉及联网插件、外部 API、敏感领域（医疗、金融）内容时，可能需要补充类目与资质材料，审核通过才能上架对应渠道。建议发布前在预览区把「正常问题 + 越界问题 + 注入攻击问题」各测一遍，别让明显漏洞跟着版本一起上线。

知识点 2：各渠道接入方式

Web 渠道最简单：发布时勾选「Web」，会得到一个 www.coze.cn/store/... 分享链接，任何人打开即可对话；如果要嵌入自己的网站，可以用两种方式：一是直接 iframe 嵌入官方页面，二是用扣子提供的Web SDK/嵌入代码在页面里挂一个可折叠的对话组件（适合做产品内客服悬浮窗）。

微信生态有两个不同入口：微信客服需要企业资质，在微信客服后台创建账号并按指引配置回调地址，用户在微信里搜索该客服账号即可对话；公众号则需要已认证的服务号/订阅号，通过扣子的公众号渠道授权绑定，用户在公众号发消息会转发给 Bot，Bot 回复再回写公众号。两者的共同前提是实名/企业认证，个人账号通常只能走 Web 渠道。

飞书是接入体验最顺滑的渠道：在扣子发布页选择飞书，扫码授权后会自动在飞书里创建一个应用机器人，用户在飞书工作台或群里 @ 机器人即可对话；飞书渠道还支持群聊卡片消息、@提及触发，适合做团队内部助手。抖音、iPhone 快捷指令、C++/Java SDK 等渠道按官方文档照做即可，原理都是「渠道负责收发消息，扣子负责大脑」。

知识点 3：API 集成与上线后的观测

要在自有系统里深度集成（比如嵌进 App、接企业 IM），走 Coze API：用 Personal Access Token 鉴权，调用 Chat 接口（阻塞式问答）或 Stream Chat 接口（流式输出，体验更好）；有状态多轮对话用 conversation_id 串联，无状态单轮则每次新建会话。集成时注意两点：Token 权限最小化、生产环境把超时和重试写好（LLM 响应可能达 30 秒以上）。

上线后要在扣子后台的「数据统计」里盯三个指标：对话量趋势（发现异常峰值）、用户问题列表（找知识库盲区）、插件/工作流失败率（发现超时和报错）。把高频但答不好的问题沉淀成新的知识库条目或工作流分支，形成「发布 → 观测 → 迭代 → 再发布」的闭环，这才算真正把 Bot 跑起来。

三、示例演示

示例一：把已发布的 Bot 嵌入自有官网页面。在扣子发布页复制「Web 嵌入」生成的代码片段，粘到页面中即可（以下为示意结构，实际代码以扣子后台复制为准）：

<!-- 放在 <body> 结束前；appId 为扣子发布页提供 -->
<script src="https://www.coze.cn/js/bot.min.js"></script>
<script>
  new CozeWebChat({
    appId: "7362************",   // 扣子发布页生成的应用 ID
    config: {
      isDrag: true,              // 悬浮窗可拖动
      dragDirection: "vertical",
      expand: false,             // 默认收起，点击展开
    },
    bizParams: {
      title: "官网智能客服",
      icon: "https://your-site.com/logo.png",
    },
  });
</script>

示例二：用 Python 调用 Coze Chat API 实现流式问答，适合集成进命令行工具或后端服务：

import os
import requests

COZE_TOKEN = os.environ["COZE_TOKEN"]
BOT_ID = "7362************"      # 发布页的 Bot ID

def chat(question: str, conversation_id: str | None = None):
    """流式调用已发布 Bot；返回 (完整回复, 会话ID) 供下一轮复用"""
    payload = {
        "bot_id": BOT_ID,
        "user_id": "u_1001",
        "stream": True,
        "auto_save_history": True,
        "additional_messages": [
            {"role": "user", "content": question, "content_type": "text"}
        ],
    }
    if conversation_id:
        payload["conversation_id"] = conversation_id

    resp = requests.post(
        "https://api.coze.cn/v3/chat",
        headers={"Authorization": f"Bearer {COZE_TOKEN}"},
        json=payload,
        stream=True,
        timeout=60,
    )
    resp.raise_for_status()
    answer, conv_id = "", conversation_id
    for line in resp.iter_lines(decode_unicode=True):
        if not line or not line.startswith("event:"):
            continue
        if line == "event: conversation.message.delta":
            pass                                  # 下一行 data 里是增量文本
        elif line == "event: conversation.message.completed":
            pass                                  # 整段回复完成，可在此落库
    return answer, conv_id

if __name__ == "__main__":
    print(chat("介绍一下你能做什么")[0])
💡 提示：生产环境请使用扣子官方 SDK（Python/Java 均提供）替代手写解析，事件类型包含 done、error、conversation.message.delta 等，SDK 会把增量拼接与错误处理封装好；上面的示例用于理解协议结构。

四、实践任务

  1. 任务 1：把前面几节做的 Bot 发布到 Web 渠道，用手机扫码验证正式版本可访问，再做一次草稿修改，确认线上仍是旧版本。
  2. 任务 2：新建一个测试版本，给开场白加一条说明后重新发布，观察版本记录里能否回滚到上一版本。
  3. 任务 3（进阶，可选）：用 iframe 或 SDK 把 Bot 嵌入一个本地 HTML 页面，在浏览器里验证悬浮窗对话正常。
  4. 任务 4（进阶，可选）：申请一个 Personal Access Token，用官方 Python SDK 写一个最小客户端，实现「同一会话连续问三轮」并保存完整对话记录。
