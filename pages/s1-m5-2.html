智能体场景选题与需求拆解

预计 0.5 天模块五 · AI 智能体快速开发

一、学习目标

  • 能够用四象限筛选法（价值、可行性、数据可得性、风险）评估并选出一个合适的智能体题目。
  • 能够把模糊的业务诉求拆成意图清单、对话流程、所需数据与工具四项产出。
  • 能够识别"不适合做成智能体"的需求，并给出替代方案。
  • 能够为选定场景写出最小可行范围（MVP），控制在 1 天内可完成。

二、核心知识点

知识点 1：好题目的四个特征

选题决定了项目上限。四个特征按重要性排序：高频且重复（每天发生 20 次的答疑，比每月一次的报表更值得做）；知识边界清晰（答案能在文档里找到，模型只需检索与表达）；容错空间大（推荐话术说错一句无伤大雅，而合同审核一字之差就是事故）；有真实用户（哪怕只有一个同事愿意每天用，也比"我觉得有用"强）。

反面清单同样重要：需要精确数值计算的（转账金额、税费）、需要实时私有数据且无法接入的、决策后果不可逆的（医疗诊断、法律结论）——这些要么用传统程序解决，要么只做辅助不做决策。

知识点 2：从诉求到需求的四件产出

拿到"做个客服助手"这类诉求后，你要产出四张清单：意图清单（用户会问什么，按频率排序，先覆盖 Top 5）；对话流程（每个意图的澄清问题、所需信息、结束标志）；数据与工具清单（要哪些文档进知识库、要哪些接口给它用）；边界与兜底（拒答什么、转人工条件、出错话术）。这四件产出直接对应智能体的提示词、知识库、插件三大配置，写完即可开工。

知识点 3：MVP 思维与验证指标

第一版只做 Top 3 意图就够。验收指标要提前定好，可量化的有：意图覆盖率（3 个核心意图是否都能触发正确流程）、知识命中率（10 条测试问题召回正确段落的比例）、人工转接率（需要人介入的对话占比）、单次解决时长。没有指标的智能体永远"看起来还行"；有了指标，每一轮提示词优化才有据可依。定指标时同时定数据收集方式——从第一天起就导出对话记录，不要等到"上线后再看"。

💡 选题时先问一句："这个场景最糟糕的结果是什么？"如果答案是"损失客户信任但可挽回"，通常适合先做；如果答案是"造成实际伤害"，那就只做辅助决策。

三、示例演示

示例一是把"做个售后客服助手"拆解成可开工需求的完整样例：

【场景】某家电品牌售后答疑
【Top 意图（按历史工单量排序）】
1. 物流查询：订单号/手机号 → 引导至查询页面或调用物流插件
2. 安装预约：品类 + 城市 → 给出可预约时段话术
3. 常见故障自助：E1/E2 报错代码 → 按知识库步骤引导
4. 保修政策：整机/主要部件年限 → 引用知识库原文回答
5. 退款投诉 → 一律转人工

【对话流程示例（意图 3）】
用户描述故障 → 确认型号 → 确认报错代码 → 检索知识库 → 给出 2-3 步自助方案
→ 询问是否解决 → 未解决则生成工单信息并转人工

【数据与工具】
知识库：安装说明书 PDF、报错代码表（Excel）、保修政策；
工具：物流查询插件（可选，第二版接入）；工单创建暂由人工承接

【边界】不承诺赔付金额、不判断产品责任、不确定时统一转人工

【MVP 范围（第 1 天）】只做意图 3 + 意图 4，其余回复转人工话术
【验证指标】10 条测试问题的意图识别正确率 ≥ 90%，知识命中率 ≥ 80%

示例二是快速打分用的选题评分表模板，每个候选场景按 1-5 分打分，总分高者优先：

场景：____________  评分人：____  日期：____

| 维度         | 权重 | 得分(1-5) | 依据（一句话）        |
| 高频重复     | 30%  |           |                       |
| 知识可得     | 25%  |           |                       |
| 容错空间     | 20%  |           |                       |
| 有真实用户   | 15%  |           |                       |
| 一天内可完成 | 10%  |           |                       |
| 加权总分     | 100% |           |                       |
💡 提示：给每个低分写一句"依据"很关键——它往往暴露出你尚未调研清楚的信息缺口，比如"不知道工单系统有没有 API"。

四、实践任务

  1. 任务 1：列出 3 个你身边的候选场景（工作/生活皆可），用评分表打分并选定一个。
  2. 任务 2：为选定场景产出四件套：意图清单、对话流程、数据与工具清单、边界与兜底话术。
  3. 任务 3：写出该场景的 MVP 范围与 2-3 个可量化验收指标，并列出 10 条测试问题。
  4. 任务 4（进阶，可选）：找一位真实用户访谈 10 分钟，验证你的意图清单是否遗漏高频问题，据此修订。

五、推荐资源

  • 📖 Coze 官方文档 — 了解平台能力边界，选题时据此判断"能不能做"。
  • 📖 Coze Bot 商店 — 浏览别人做好的智能体，找选题灵感并分析其意图设计。
  • 📖 Dify 官方文档 — 看另一平台的能力清单，横向校准你的需求拆解。
  • 📖 NN/g：用户旅程地图 — 把对话流程画成旅程图的方法，适合设计多轮澄清。

六、自检清单

  • 我能用四象限/评分表说明为什么选这个题、为什么不选别的题吗？
  • 我的意图清单是否按真实频率排序，并明确只做 Top 3？
  • 我是否写清了拒答边界与转人工条件？
  • 我的验收指标是否可量化，且从第一天就有数据收集方案？
