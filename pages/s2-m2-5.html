接口测试（Swagger）与部署（Uvicorn/Docker）

预计 1 天模块二 · FastAPI

一、学习目标

  • 能够读懂并利用 Swagger UI / OpenAPI 完成接口调试、分享与前后端协作。
  • 能够用 pytest + TestClient 为接口编写自动化测试，并用依赖覆盖（overrides）隔离外部资源。
  • 能够配置 Uvicorn 在开发与生产环境运行应用，说清 reload 与 worker 数的选择依据。
  • 能够编写 Dockerfile 把应用打包成镜像并运行，完成从代码到容器的最小部署闭环。

二、核心知识点

知识点 1：Swagger 与 OpenAPI——接口即文档

FastAPI 启动后自动生成 OpenAPI JSON（访问 /openapi.json），并内置两个可视化界面：/docs（Swagger UI，可直接点 Try it out 发请求）与 /redoc（更适合阅读的排版）。文档内容全部来自你的路由与类型标注，所以「写好模型 = 写好文档」，代码与文档不同步的问题从机制上被消除。协作用法：① 开发中用 /docs 手测新接口；② 把 openapi.json 交给前端用在线转换器生成类型定义，或用 openapi-generator 生成多语言客户端；③ 生产环境可关闭 /docs（app = FastAPI(docs_url=None, redoc_url=None)）避免暴露接口面，内网工具则建议保留。给路由补充 summary、description、response_description、tags、status_code 能显著提升文档质量。

知识点 2：接口自动化测试

测试分层：单元测试测纯函数（快、多）、接口测试测 HTTP 行为（真实、关键路径必测）。FastAPI 提供 TestClient（starlette 内置，基于 httpx），无需启动服务器即可 client.get("/items") 直接拿状态码与响应 JSON，非常适合放进 pytest。核心技巧是 依赖覆盖：app.dependency_overrides[get_db] = lambda: fake_db 把数据库、外部 API 替换成假实现，测试才能快速、可重复、不依赖外网；用 fixture（conftest.py）在每个测试前重置应用与假数据，结束后 dependency_overrides.clear()。断言至少覆盖三类：正常路径 200/201 与响应体结构、边界与非法输入 422、业务错误 401/404。异步路由用同步 TestClient 即可（其内部会运行事件循环），无需额外安装 pytest-asyncio。

知识点 3：Uvicorn——ASGI 服务器

FastAPI 应用是 ASGI 应用，需要 ASGI 服务器运行，Uvicorn 是最常用的一个：uvicorn main:app --host 0.0.0.0 --port 8000。开发用 --reload 监听代码变动自动重启（绝不能用于生产，额外开销且不安全）；生产用 --workers N，经验公式 N = 2×CPU核数 + 1，I/O 密集（大模型流式服务）可适当多配，CPU 密集则受 GIL 限制、应考虑多进程外的方案。生产还常以 gunicorn -k uvicorn.workers.UvicornWorker 或 systemd/ supervisor 托管实现守护与优雅重启；Linux 下可配合 uvloop/ttloop（uvicorn[standard] 自带）提升吞吐。日志统一走 --log-level info 或配置文件，反向代理（Nginx）负责 TLS、静态资源与 gzip。

知识点 4：Docker 打包与运行

容器把应用与其依赖（解释器、库、系统包）一起封进镜像，实现「在我机器上能跑」到「哪里都能跑」。写 Dockerfile 的要点：① 基础镜像选 python:3.11-slim（体积小、够用）；② 先 COPY 依赖文件再 COPY 源码并单独执行 pip install——利用分层缓存，改代码不重装依赖；③ 写 .dockerignore 排除 .venv、__pycache__、.git、测试数据，避免镜像膨胀与密钥泄露；④ 容器内不要装开发工具，固定依赖版本保证构建可复现。运行用 docker run -p 8000:8000 -e SECRET_KEY=... image，端口「宿主:容器」映射，密钥一律用 -e 或编排平台注入、绝不写进镜像。上生产还需健康检查（HEALTHCHECK 或 /health 路由）、非 root 用户运行、多容器用 docker compose 编排。

三、示例演示

示例一：pytest 接口测试（含依赖覆盖隔离数据库），文件名 test_api.py，运行 pytest -v：

from fastapi import Depends, FastAPI, HTTPException
from fastapi.testclient import TestClient

app = FastAPI()

FAKE_DB = {"items": {"1": {"id": 1, "name": "知识卡片"}}}

def get_db():
    return FAKE_DB                    # 生产实现是从连接池取会话

@app.get("/items/{item_id}")
def get_item(item_id: int, db: dict = Depends(get_db)):
    item = db["items"].get(str(item_id))
    if item is None:
        raise HTTPException(404, "物品不存在")
    return item

# 用测试假库替换真实依赖，测试间互不污染
app.dependency_overrides[get_db] = lambda: {"items": {}}

client = TestClient(app)

def test_get_existing_item():
    app.dependency_overrides[get_db] = lambda: FAKE_DB
    resp = client.get("/items/1")
    assert resp.status_code == 200
    assert resp.json()["name"] == "知识卡片"

def test_not_found_returns_404():
    resp = client.get("/items/999")
    assert resp.status_code == 404
    assert resp.json()["detail"] == "物品不存在"

def test_path_param_must_be_int():
    resp = client.get("/items/abc")   # 类型不合法 → 框架自动 422
    assert resp.status_code == 422

def test_response_has_no_extra_fields():
    body = client.get("/items/1").json()
    assert set(body.keys()) == {"id", "name"}   # 验证字段白名单

示例二：Dockerfile 与构建运行命令（放在项目根目录）：

# ---------- Dockerfile ----------
FROM python:3.11-slim

ENV PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1

WORKDIR /app

# 先拷贝依赖描述文件：只有依赖变化时才重建这一层
COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt
# requirements.txt 内容（固定版本保证可复现）：
# fastapi==0.115.0
# uvicorn[standard]==0.30.6
# httpx==0.27.2

# 再拷贝源码：业务代码变更不会触发依赖重装
COPY src/ ./src/
COPY main.py ./

RUN useradd -m appuser && chown -R appuser /app
USER appuser                     # 非 root 运行，降低风险

EXPOSE 8000
HEALTHCHECK --interval=30s --timeout=3s \
  CMD python -c "import urllib.request; \
      urllib.request.urlopen('http://127.0.0.1:8000/health')"

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

# ---------- 构建与运行 ----------
docker build -t ai-agent-service:1.0 .
docker run -d --name agent -p 8000:8000 \
  -e SECRET_KEY=change-me ai-agent-service:1.0
curl http://127.0.0.1:8000/health     # 验证容器内服务可用
💡 提示：本地开发不想装 Docker 也能验证——先 pytest 跑通接口测试，再 uvicorn 直接起服务用 /docs 手测，最后才 build 镜像。三步对应「逻辑正确 → 行为正确 → 环境可复现」。

四、实践任务

  1. 任务 1：为你的 FastAPI 项目写 4 个以上 pytest 用例，覆盖成功、404、422 三类断言，并用 app.dependency_overrides 把数据库依赖换成假实现，确认不连库也能跑绿。
  2. 任务 2：打开 /docs 与 /redoc，给全部路由补上 summary、tags、status_code，导出 /openapi.json 并检查其中是否包含你补充的描述与示例。
  3. 任务 3：分别用 uvicorn --reload（开发）与 --workers 2（模拟生产）启动同一应用，压测或观察日志差异，写下 worker 数与机器核数、请求类型的对应关系。
  4. 任务 4（进阶，可选）：编写 Dockerfile 与 .dockerignore 构建镜像，用 docker run 起容器访问 /health；故意删掉依赖层缓存写法（把 COPY src 提到 pip install 前）对比两次 build 的耗时差异。
