Spring IoC 与 AOP 原理

预计 1 天模块一 · Java / SpringBoot

一、学习目标

  • 能够解释 IoC 容器解决什么问题，说清 Bean 的创建、依赖注入与生命周期回调过程。
  • 能够熟练使用构造器注入与常用注解（@Component/@Service/@Configuration）组织 Bean。
  • 能够解释 AOP 的核心概念（切点、通知、切面），并说明 JDK 动态代理与 CGLIB 的区别。
  • 能够编写一个实战切面（如耗时日志或权限校验），并解释同类内部调用为何会失效。

二、核心知识点

知识点 1：IoC——把对象的创建权交出去

没有 IoC 时，Service 里要自己 new 依赖的 DAO，对象间强耦合：换实现要改所有调用点，测试时无法替换假对象。控制反转（IoC）把"创建与装配对象"的权力交给 Spring 容器：开发者只声明"我需要什么"（构造器参数），容器负责创建、注入、管理生命周期。Spring Boot 启动时扫描 @Component/@Service/@Repository/@Controller/@Configuration 标注的类，注册为 BeanDefinition，实例化并注入，最后放入 ApplicationContext 供查找。注入方式中构造器注入是首选：依赖可声明为 final 保证不可变、天然支持循环依赖检测、测试时直接 new 即可，无需依赖容器。

生命周期要点：容器创建 → 依赖注入 → @PostConstruct 初始化（建立连接、预热缓存）→ 对外可用 → 容器关闭 → @PreDestroy 释放资源。常见坑：把有状态的 Bean 默认写成单例却在字段里存请求级数据，导致并发串数据。

知识点 2：AOP——把横切逻辑抽出来

日志、鉴权、耗时统计、事务这些逻辑散落在每个方法里既重复又难维护，AOP（面向切面编程）把它们抽成"切面"，在运行期动态织入。核心概念：切点（Pointcut）定义在哪些方法上生效（通常用表达式如 execution(* com.example.service.*.*(..))）；通知（Advice）定义做什么（@Before/@After/@Around/@AfterReturning/@AfterThrowing）；切面（Aspect）把两者组装起来。@Around 最强大，既能包住目标方法做前后处理，也能改写返回值、吞掉异常或重试。

原理层面：Spring 默认对实现了接口的 Bean 用 JDK 动态代理（基于接口的 Proxy），未实现接口时用 CGLIB（生成目标类的子类）；Spring Boot 2.x 起默认强制使用 CGLIB 代理。这带来一个著名坑：同类方法内部调用不经过代理对象，@Transactional、@Async 会失效——解决办法是注入自身代理、拆分类，或通过 AopContext.currentProxy() 获取代理对象。

三、示例演示

示例一：构造器注入组织 Service 与依赖：

// TicketService.java
@Service
public class TicketService {
    private final TicketRepository repository;
    private final Notifier notifier;

    // 构造器注入：依赖清晰、可测试
    public TicketService(TicketRepository repository, Notifier notifier) {
        this.repository = repository;
        this.notifier = notifier;
    }

    @Transactional
    public Ticket close(long id) {
        Ticket ticket = repository.findById(id)
                .orElseThrow(() -> new IllegalArgumentException("工单不存在: " + id));
        ticket.close();
        notifier.send("工单 " + id + " 已关闭");
        return ticket;
    }
}

示例二：耗时统计切面，自动作用于 service 包所有公开方法：

// PerfAspect.java
@Aspect
@Component
public class PerfAspect {
    private static final Logger log = LoggerFactory.getLogger(PerfAspect.class);

    @Around("execution(* com.example.service.*.*(..))")
    public Object measure(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.nanoTime();
        try {
            return pjp.proceed();          // 执行目标方法
        } finally {
            long cost = (System.nanoTime() - start) / 1_000_000;
            log.info("{}.{} 耗时 {} ms",
                    pjp.getTarget().getClass().getSimpleName(),
                    pjp.getSignature().getName(), cost);
        }
    }
}
💡 提示：调试 Bean 问题时先用 Spring Boot Actuator 的 /actuator/beans 或在 IDE 里断点 refresh() 流程查看容器中的 Bean 与注入关系；遇到"注解不生效"，第一步永远是确认对象是否真的是容器里的代理。

四、实践任务

  1. 任务 1：创建 TicketService + TicketRepository（内存实现即可），全部改造成构造器注入，验证去掉 @Autowired 后仍能正常注入。
  2. 任务 2：编写 PerfAspect 耗时切面，调用三个不同的 Service 方法，观察日志输出并解释切点表达式匹配规则。
  3. 任务 3：在 Service 中写一个自调用方法加 @Async（或 @Transactional），复现"内部调用不走代理导致注解失效"，再用注入自身代理的方式修复。
  4. 任务 4（进阶，可选）：用 @PostConstruct/@PreDestroy 实现一个启动时预热、关闭时释放的资源类，并通过日志验证生命周期顺序。
