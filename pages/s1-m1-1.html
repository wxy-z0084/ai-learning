阶段一 · 指挥AI写软件

账号注册与工作区管理

预计 0.5 天模块一 · Coze 平台使用

一、学习目标

  • 能够独立完成扣子（Coze，coze.cn）账号注册、实名认证，并理解国内版与海外版（coze.com）的差异。
  • 能够创建个人/团队工作区，说明个人空间与团队空间在协作、权限上的区别。
  • 能够为工作区添加协作成员、设置角色权限，完成一个最小可用的团队协作环境搭建。
  • 能够理解扣子的资源层级（工作区 → Bot / 插件 / 工作流 / 知识库），为后续开发打好组织基础。

二、核心知识点

知识点 1：注册、登录与实名认证

扣子国内版官网为 https://www.coze.cn，支持手机号验证码注册，也可以用抖音、飞书、微信等账号授权登录；海外版 coze.com 面向海外用户，两者账号体系、模型资源和发布渠道都不互通，本课程统一使用国内版。注册完成后建议第一时间做实名认证（个人或企业认证均可），因为实名等级直接决定资源配额：可创建的 Bot 数量、知识库容量、以及能调用的模型范围都与账号等级挂钩，未认证账号很多高级功能会受限。

常见坑：用海外版注册后发现没有微信发布渠道，或者用团队邮箱注册后人员无法互见——根源都是选错了版本或注册主体，建议开工前先和团队确认统一用 coze.cn。

知识点 2：个人空间 vs 团队空间

登录后左侧就是工作区列表。个人空间适合快速实验：创建的 Bot、插件、知识库只有你自己可见可编辑，资源按个人配额计算。团队空间面向多人协作：由空间所有者创建，通过邀请成员加入，成员按角色获得权限。扣子的空间角色通常包括所有者（Owner）、管理员（Admin）、普通成员（Member）和访客（Guest）：所有者掌握空间设置与成员管理，管理员可管理大部分资源，普通成员可创建和编辑自己权限内的资源，访客一般只读。

操作要点：先把未来要一起开发 Bot 的同事拉进团队空间，再开始建资源；如果在个人空间建完再迁移，会遇到权限继承丢失、资源无法跨空间转移的麻烦。

知识点 3：资源层级与配额管理

工作区是所有资源的容器，内部包含 Bot（智能体）、插件、工作流、知识库、数据库、记忆等资源，它们共享工作区上下文：同一空间内的 Bot 可以直接引用该空间下的插件、工作流和知识库，跨空间引用则需要额外的共享机制。因此合理的组织方式是：一个业务场景对应一个工作区，比如「客服机器人」和「内部数据助手」分属两个空间，避免资源互相污染。

配额方面，重点盯住三个上限：知识库存储容量（按字符/文件大小计）、工作流每日执行次数（影响 Bot 调用量）、模型调用额度。个人版额度有限，建议开发期用小数据集联调，正式上线前再扩容。

三、示例演示

下面是一份可直接照做的「从零到团队协作环境」操作清单，按顺序执行约 30 分钟即可完成：

# 扣子（coze.cn）工作区初始化清单（浏览器操作，无代码）

1. 打开 https://www.coze.cn → 手机号注册 → 完成个人实名认证
2. 点击左上角头像 → 「切换空间」→ 「创建团队空间」
   - 空间名称：AI客服机器人项目
   - 描述：内部客服场景，Bot 对外发布到微信客服
3. 进入团队空间 → 「成员管理」→ 「邀请成员」
   - 输入同事手机号/邮箱 → 角色选择「管理员」（核心开发）
   - 普通运营同事角色选「普通成员」
4. 空间设置 → 资源配额页：记录知识库容量上限、工作流执行上限
5. 左侧导航依次点开：Bot / 插件 / 工作流 / 知识库，确认初始为空

如果你倾向用 API 或脚本方式管理组织资源，扣子开放平台也提供 OpenAPI（如通过 access token 查询工作区资源列表），可以像下面这样做一个配额巡检脚本的雏形：

import os
import requests

# 在 https://www.coze.cn/open/oauth/apps 创建应用获取 Personal Access Token
COZE_TOKEN = os.environ["COZE_TOKEN"]
BASE = "https://api.coze.cn"

def list_bots(page_size=20):
    """列出当前 token 归属空间下的 Bot，用于核对资源是否建在正确的工作区"""
    resp = requests.post(
        f"{BASE}/v1/spaces/bots",
        headers={"Authorization": f"Bearer {COZE_TOKEN}"},
        json={"page_index": 1, "page_size": page_size},
        timeout=15,
    )
    resp.raise_for_status()
    data = resp.json()
    bots = data.get("data", {}).get("bots", [])
    for b in bots:
        print(f"Bot 名称: {b.get('bot_name')}  状态: {b.get('status')}  空间: {b.get('space_id')}")
    return bots

if __name__ == "__main__":
    list_bots()
💡 提示：Personal Access Token 等同于账号密码，务必存放在环境变量中，不要提交进代码仓库；团队场景建议给每个开发者发独立 Token，便于审计与吊销。

四、实践任务

  1. 任务 1：注册 coze.cn 账号并完成实名认证，截图记录你的账号等级与当前各项资源配额数字。
  2. 任务 2：创建一个名为「AI学习实验」的团队空间，把你的另一个手机号或一位同学邀请为「普通成员」，再自行升级为「管理员」，验证权限差异（如访客能否编辑 Bot）。
  3. 任务 3：在该空间下建一个空白 Bot 占位（名字随意），然后建一个知识库，观察两者是否出现在同一空间的资源列表中，验证资源共享关系。
  4. 任务 4（进阶，可选）：在开放平台创建一个应用拿到 Personal Access Token，用上面的 Python 脚本列出空间内的 Bot，确认 API 与界面看到的资源一致。

五、推荐资源

  • 📖 扣子官方文档 — 入门、空间管理、资源配额的权威说明，遇到界面变动以这里为准。
  • 📖 扣子 Bot 商店 — 浏览社区优秀 Bot，感受不同场景下资源组织方式，注册后即可访问。
  • 📖 扣子开放平台 — OpenAPI 与 Personal Access Token 的申请入口，做自动化管理时用。
  • 📖 飞书官网 — 扣子国内版与飞书生态深度集成，团队协作账号可直接打通。
