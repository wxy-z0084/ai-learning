依赖注入与中间件

预计 0.5 天模块二 · FastAPI

一、学习目标

  • 能够用 Depends 把「获取当前用户、开数据库会话、读配置」等公共逻辑抽成可复用依赖。
  • 能够使用 yield 依赖 管理资源的申请与释放，并解释同一请求内依赖只执行一次的缓存行为。
  • 能够为路由、路由器、应用三个层级挂载依赖，实现「一组接口统一鉴权/统一校验」。
  • 能够编写 HTTP 中间件 完成请求日志、耗时统计与 CORS 配置，并说清「用依赖还是用中间件」的判断标准。

二、核心知识点

知识点 1：Depends——把公共逻辑声明出来

依赖注入（Dependency Injection, DI）的核心是：处理函数不再自己「制造」它需要的东西，而是声明「我需要什么」，框架负责在调用前把结果准备好。在 FastAPI 中，参数写成 db: Session = Depends(get_db) 即可——框架看到 Depends 就去执行 get_db()，把返回值注入进来。好处有三：① 公共代码（连接、校验、分页）只写一处；② 依赖本身也是参数，可继续声明自己的依赖形成依赖树（get_current_user 依赖 oauth2_scheme，oauth2_scheme 依赖 request）；③ 依赖函数带类型标注与 Query/Path 声明时，会自动参与文档生成与校验。

缓存规则：同一个请求内，相同的依赖（同一函数、同参数）只执行一次，多个路由参数共享同一个对象——这正是「一次请求一个数据库会话」的实现原理。但要注意别依赖这个副作用：一个有状态的全局可变对象被多请求共享时，缓存反而会串状态。

知识点 2：yield 依赖——资源的申请与清理

数据库连接、事务、锁这类资源需要「用完归还」，用 yield 依赖 最合适：yield 之前的代码在请求处理前执行（申请资源），yield 的值注入路由，yield 之后的代码在响应发送后执行（清理），且无论成功失败都会跑（类似 finally）。事务型依赖常用 try: yield session; session.commit() / except: rollback / finally: close 的结构。坑：yield 之后不能再返回值（返回值会被忽略并告警）；也不要在一个请求里混用多个各自开连接的依赖，否则可能超过连接池上限。

知识点 3：依赖的挂载层级

Depends 可以出现在四个位置，作用范围依次扩大：① 函数参数——只作用于该路由；② APIRouter(dependencies=[...])——作用于该路由器下所有路由（一组接口统一校验）；③ FastAPI(dependencies=[...])——全局生效（每个请求都执行）；④ include_router 时传入——只对引入的那批路由生效。注意：挂在路由上的依赖默认不使用注入值（只是执行副作用，如校验权限），若要拿到返回值必须在函数参数里再写一遍 Depends。依赖的执行顺序是「树的深度优先」：先跑最深层依赖。

知识点 4：中间件与选择标准

中间件（middleware）是包在「整个应用」外面的一层：请求进入 → 中间件代码 → 路由处理 → 响应返回 → 中间件代码。用 @app.middleware("http") 定义，函数签名接收 Request 并必须 call_next(request) 后拿到响应再返回；request.body() 只能在 call_next 前读（读过 body 再交给路由会导致空体）。典型用途：请求 ID 与访问日志、耗时统计、统一加响应头、限流计数；跨域用内置的 CORS middleware（add_middleware CORSMiddleware）。

选择标准：需要注入值给处理函数、只对部分路由生效、逻辑与业务紧密相关（鉴权、分页）→ 用依赖；对所有请求无差别生效、只关心进出流量本身（日志、压缩、超时、CORS）→ 用中间件。经验法则：能用依赖解决的别写中间件，因为依赖更可测、更局部化。

三、示例演示

示例一：一个 yield 数据库依赖 + 分页依赖 + 路由级权限依赖的组合，是生产项目的标准写法：

from typing import Iterator
from fastapi import Depends, FastAPI, Header, HTTPException, Query

app = FastAPI()

# ---------- 资源型依赖：yield 管理申请与清理 ----------
def get_db() -> Iterator[dict]:
    db = {"conn": "fake-connection", "in_tx": True}
    try:
        yield db            # 注入给路由使用
    finally:
        db["in_tx"] = False # 无论成功失败都会执行清理
        print("连接已归还连接池")

# ---------- 校验型依赖：把参数解析也交给框架 ----------
def pagination(
    limit: int = Query(20, ge=1, le=100),
    offset: int = Query(0, ge=0),
) -> dict:
    return {"limit": limit, "offset": offset}

# ---------- 身份型依赖：可被其他依赖继续复用 ----------
def get_current_user(x_api_key: str = Header(...)) -> dict:
    if x_api_key != "dev-key":
        raise HTTPException(status_code=401, detail="无效的 API Key")
    return {"user": "alice", "role": "admin"}

def require_admin(user: dict = Depends(get_current_user)) -> dict:
    if user["role"] != "admin":
        raise HTTPException(status_code=403, detail="需要管理员权限")
    return user

@app.get("/items")
def list_items(
    page: dict = Depends(pagination),
    db: dict = Depends(get_db),          # 与业务代码完全解耦
    user: dict = Depends(get_current_user),
):
    start = page["offset"]
    return {"user": user["user"], "db": db["conn"],
            "items": list(range(start, start + page["limit"]))}

@app.get("/admin/stats", dependencies=[Depends(require_admin)])
def stats():
    """路由级依赖只做执行与拦截，不需要返回值"""
    return {"qps": 128, "error_rate": 0.002}

示例二：中间件统计每个请求的耗时并加上请求 ID，配合 CORS 配置：

import time
import uuid
from fastapi import FastAPI, Request
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI()

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173"],  # 前端开发服务器地址
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

@app.middleware("http")
async def add_timing(request: Request, call_next):
    request_id = uuid.uuid4().hex[:8]
    start = time.perf_counter()
    response = await call_next(request)      # 进入路由并拿到响应
    elapsed_ms = (time.perf_counter() - start) * 1000
    response.headers["X-Request-ID"] = request_id
    response.headers["X-Process-Time"] = f"{elapsed_ms:.1f}ms"
    print(f"[{request_id}] {request.method} {request.url.path} "
          f"-> {response.status_code} {elapsed_ms:.1f}ms")
    return response

@app.get("/ping")
def ping():
    return {"msg": "pong"}
💡 提示：想看依赖链的执行顺序，写几个 print 打开 /docs 逐个调用即可——依赖树按深度优先执行，yield 依赖的清理代码总在响应发出之后运行。

四、实践任务

  1. 任务 1：写一个 get_settings 依赖读取环境变量（或返回配置字典），在三个路由中注入；打印验证「同一请求内只执行一次」的缓存行为。
  2. 任务 2：实现 yield 版本的 get_db（可用 dict 模拟连接池），在依赖里做 commit/rollback/finally close，并写一个会抛异常的路由验证回滚与关闭都被执行。
  3. 任务 3：把「API Key 校验」依赖分别挂到单个路由、APIRouter、FastAPI(dependencies=...) 三个层级，对比各自生效范围与 401 行为。
  4. 任务 4（进阶，可选）：编写中间件给每个请求生成 Request-ID 并统计耗时；再把「鉴权」从中间件改造成依赖，写下你观察到的两者差异（能否注入、能否只作用于部分路由）。
