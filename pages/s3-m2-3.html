权限认证（Spring Security / Sa-Token）

预计 1 天模块二 · 企业级单体项目开发

一、学习目标

  • 学完本节后，你能够区分认证（Authentication）与授权（Authorization），并解释 Session 与 Token 两种方案的取舍。
  • 你能够基于 RBAC 模型（用户-角色-权限）设计权限表结构，并写出权限判断逻辑。
  • 你能够用 Sa-Token 完成登录、鉴权、权限拦截的完整链路，或用 Spring Security 配置一个过滤器链。
  • 你能够识别密码明文、放行路径过宽、密钥泄漏等常见安全问题并修复。

二、核心知识点

知识点 1：认证与授权，Session 与 Token

认证回答"你是谁"（校验用户名密码或 Token），授权回答"你能做什么"（判断是否有某个权限点）。企业系统普遍采用 RBAC 模型：用户 → 角色 → 权限三张关联表，权限既可以是"菜单/按钮"也可以是"接口标识"，这样新增岗位只需改角色的权限集合，不动代码。

会话方案上，传统 Session 把状态存在服务器内存，多实例部署时需要共享 Session（Redis）；Token（常用 JWT）把用户身份与过期时间签名后下发，服务器无状态，天然适合分布式。代价是 Token 一旦签发难以主动失效，需要配合黑名单（Redis 存 tokenId）或缩短有效期加刷新机制。选择标准：内网后台、要求可强制下线的系统可选 Sa-Token + Redis；跨端、跨服务的开放接口更适合 JWT。

知识点 2：Spring Security 的过滤器链模型

Spring Security 的核心是一串安全过滤器（FilterChain）：请求先经过 UsernamePasswordAuthenticationFilter 处理登录，再经过 ExceptionTranslationFilter、FilterSecurityInterceptor 做权限判断，最终才到你的 Controller。自定义配置的入口是定义一个 SecurityFilterChain Bean：配置哪些路径 permitAll（登录、文档接口）、哪些 authenticated、登录表单走什么 AuthenticationManager、密码用 BCryptPasswordEncoder 存储。方法级权限在类或方法上加 @PreAuthorize("hasAuthority('user:delete')")，需开启 @EnableMethodSecurity。

知识点 3：Sa-Token 的轻量方案与选型建议

Sa-Token 是国内流行的轻量鉴权框架，API 直观：StpUtil.login(id) 登录、StpUtil.logout() 注销、StpUtil.checkPermission("xxx") 校验权限（无权限抛异常）、StpUtil.getLoginIdAsLong() 取当前用户；配合 SaInterceptor 注册路由拦截器即可保护接口。它的 token 可配置存 Redis，支持同端互斥登录、踢人下线、临时 token 等开箱即用的能力。选型经验：Spring Security 生态标准、与 OAuth2/OIDC 集成好但配置繁琐；Sa-Token 上手快、中文文档完善、业务型后台开发效率更高。无论用哪个，都要记住三件事：密码永远 BCrypt 加盐哈希、密钥与数据库连接串放环境变量或配置中心、放行路径只写真正公开的接口（Swagger、健康检查）。

三、示例演示

示例一：Sa-Token 的登录与权限拦截，引入依赖 sa-token-spring-boot-starter、sa-token-redis-jackson 后即可使用：

// 登录接口
@PostMapping("/login")
public R<String> login(@Valid @RequestBody LoginDTO dto) {
    // 1. 查询用户并校验密码（密码用 BCrypt 比对）
    User user = userService.getByUsername(dto.getUsername());
    if (user == null || !passwordEncoder.matches(dto.getPassword(), user.getPasswordHash())) {
        throw new BizException(10001, "用户名或密码错误");
    }
    // 2. 登录并签发 token
    StpUtil.login(user.getId());
    StpUtil.getSession().set("user", user.getUsername());
    return R.ok(StpUtil.getTokenValue());
}

// 拦截器注册：除 login、doc.html 外全部需要登录
@Configuration
public class SaTokenConfig implements WebMvcConfigurer {
    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new SaInterceptor(handle ->
                StpUtil.checkLogin()))
            .addPathPatterns("/**")
            .excludePathPatterns("/login", "/doc.html", "/error");
    }
}

// 权限校验：在需要的接口上直接写
@GetMapping("/orders/{id}")
public R<OrderVO> detail(@PathVariable Long id) {
    StpUtil.checkPermission("order:query");  // 无权限抛 NotPermissionException
    return R.ok(orderService.detail(id));
}

示例二：Spring Security 的最小可用过滤器链配置，两种方案可对照理解：

@Configuration
@EnableMethodSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain filterChain(HttpSecurity http) throws Exception {
        http.csrf(csrf -> csrf.disable())
            .sessionManagement(s -> s.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/login", "/doc.html", "/v3/api-docs/**").permitAll()
                .anyRequest().authenticated())
            .exceptionHandling(e -> e.authenticationEntryPoint((req, res, ex) -> {
                res.setStatus(401);
                res.setContentType("application/json;charset=UTF-8");
                res.getWriter().write("{\"code\":40100,\"message\":\"未登录或登录已过期\"}");
            }));
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }
}
💡 提示：上线前用三个必测用例自检——未登录访问受保护接口是否返回统一 401 JSON、低权限账号访问高权限接口是否被拦截、错误密码连续多次登录是否触发限流或锁定。

四、实践任务

  1. 任务 1：设计并建表 user / role / permission 及两张关联表，写入至少 2 个角色（普通用户、管理员）和 5 个权限点。
  2. 任务 2：基于 Sa-Token 完成登录、获取当前用户、登出三个接口，验证 token 在 Redis 中的存取与注销后失效。
  3. 任务 3：给"删除订单"接口加上 order:delete 权限校验，分别用有权限和无权限的账号调用，确认结果差异并返回统一错误码。
  4. 任务 4（进阶，可选）：实现"同一账号只允许一个有效登录"（新登录踢掉旧 token），并写清楚这对前端 token 失效处理的影响。
