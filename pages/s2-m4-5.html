阶段二 · 智能体开发

LangGraph 多步智能体工作流

预计 1.5 天模块四 · LangChain

一、学习目标

  • 能够说出 AgentExecutor 黑盒循环的局限，并解释为什么复杂流程要用图（状态机）来显式编排。
  • 能够用 StateGraph 完成"定义状态 → 添加节点 → 连接边/条件边 → 编译执行"的完整开发流程。
  • 能够设计合理的 State 结构（TypedDict + reducer），并实现"智能体 ↔ 工具"的循环图。
  • 能够接入 Checkpointer 实现断点持久化、人工审批（interrupt）与多轮会话恢复。

二、核心知识点

知识点 1：从 AgentExecutor 到图编排

上一节的 AgentExecutor 是一个"模型说啥就干啥"的通用循环，优点是省事，缺点也正在于此：流程不可见、不可控。真实业务往往需要固定骨架：先做安全审核 → 再检索 → 再生成 → 生成结果涉及退款就必须走人工审批 → 才能执行。这类"部分确定、部分由模型决定"的流程，用 AgentExecutor 只能靠提示词祈求模型配合，非常脆弱。

LangGraph 把智能体建模为一张有状态的图：节点（Node）是执行单元（调模型、调工具、跑函数），边（Edge）决定流转，条件边（Conditional Edge）让模型/业务规则决定走向，共享状态（State）在节点间传递数据。它带来三个质变：流程显式可读（图即文档）、每一步可持久化与恢复（Checkpointer）、可插入人工环节（interrupt）——这是把 Demo 变成生产系统的分水岭。

知识点 2：State 设计是图的灵魂

State 是所有节点共享的数据结构，通常用 TypedDict 定义。关键机制是 reducer（规约函数）：字段声明为 Annotated[list, add_messages] 时，节点返回的消息会追加到列表而不是覆盖；不加 reducer 的普通字段则是后者覆盖前者。设计原则：① 只放跨节点需要的数据（消息历史、检索结果、审批状态、草稿内容）；② 消息类字段一定用 add_messages，否则并行节点会互相覆盖；③ State 尽量小而稳定，它的每次变化都会被 Checkpointer 记录。

知识点 3：节点、边与循环

建图四步：StateGraph(State) 建图 → add_node("名", 函数) 加节点（函数签名 state: State -> dict，返回值按 reducer 规则合并进状态）→ add_edge 连固定边、add_conditional_edges 连条件边 → compile() 编译为可执行图。入口用 START、出口用 END。条件边通过一个路由函数读取 State 返回下一节点名，从而实现分支；把条件边指回之前的节点就形成循环——"思考 → 调工具 → 观察 → 再思考"正是这样建模的。图支持并行分支（一条边连多个后续节点）和汇总节点，天然适合"多路检索后汇总生成"。

知识点 4：持久化、人工审批与多智能体

编译时传入 checkpointer=MemorySaver()（开发）或 SqliteSaver/PostgresSaver（生产），每次执行都会存快照，用 thread_id 标识会话——同一 thread 可以 get_state() 查看进度、update_state() 修正状态、从中断处继续执行。人工审批：在审批节点调用 interrupt() 暂停图，人工确认后用 Command(resume=...) 恢复。多智能体协作的常见拓扑：Supervisor（主管）模式——一个协调节点根据任务类型分发给检索专家、编码专家等子图，以及网络（handoff）模式——节点之间互相移交控制权。起步建议先用 Supervisor，容易调试也容易限权。

三、示例演示

示例一：定义带 reducer 的状态，构建"生成 → 风险判断 → 人工审批"的条件分支图：

# pip install langgraph langchain langchain-openai
from typing import Annotated, TypedDict
from langchain_core.messages import AIMessage, HumanMessage
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages

class State(TypedDict):
    messages: Annotated[list, add_messages]   # reducer：追加而非覆盖
    need_review: bool                          # 普通字段：节点返回值直接覆盖

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
RISKY_WORDS = ["退款", "删除", "转账"]

def generate(state: State):
    reply = model.invoke(state["messages"])
    flagged = any(w in reply.content for w in RISKY_WORDS)
    return {"messages": [reply], "need_review": flagged}

def route(state: State):
    return "approve" if state["need_review"] else END      # 条件边：按状态选走向

def approve(state: State):
    # 真实项目在这里发起人工审批（如发企业微信/工单），通过后再放行
    return {"messages": [AIMessage("[已通过人工审批，允许执行]")]}

builder = StateGraph(State)
builder.add_node("generate", generate)
builder.add_node("approve", approve)
builder.add_edge(START, "generate")
builder.add_conditional_edges("generate", route, {"approve": "approve", END: END})
builder.add_edge("approve", END)
app = builder.compile()

result = app.invoke({"messages": [HumanMessage("帮我退掉订单 SO2024001")], "need_review": False})
for m in result["messages"]:
    print(m.type, "|", m.content)

示例二：接入 Checkpointer，让流程可中断、可恢复、可多轮会话：

from langgraph.checkpoint.memory import MemorySaver   # 生产改用 SqliteSaver/PostgresSaver

app = builder.compile(checkpointer=MemorySaver())
cfg = {"configurable": {"thread_id": "会话-1001"}}

# 第一步：执行到需要审批的节点（节点内调用 interrupt() 即会挂起并持久化）
# app.invoke({"messages": [HumanMessage("执行删除操作")]}, cfg)

state = app.get_state(cfg)                 # 查看当前进度与状态
print(state.next)                          # 例如 ('approve',) —— 停在审批节点
# 人工在后台批准后，携带结果恢复执行：
# app.invoke(Command(resume={"approved": True}), cfg)
# 换 thread_id 即为全新会话；同一 thread 重启进程后仍能继续（PostgresSaver 场景）
💡 提示：LangGraph 提供预建好的 ReAct 智能体（langgraph.prebuilt 的 create_react_agent，参数在不同版本间略有差异），几分钟即可跑通"模型+工具"循环；但只要流程涉及固定步骤或人工审批，就应回到 StateGraph 手动建图——那才是 LangGraph 的真正价值所在。

四、实践任务

  1. 任务 1：不使用任何大模型，纯函数节点实现"订单校验 → 库存扣减 → 生成单据"的线性图，打印每次执行后的 State 快照，理解状态流转。
  2. 任务 2：在示例一基础上加入检索节点：先检索知识库再生成，检索结果存入 State 供审批节点展示给人工。
  3. 任务 3：用 SqliteSaver 持久化 Checkpointer，模拟"执行到一半杀掉进程，重启后从断点恢复"，验证 thread_id 机制。
  4. 任务 4（进阶，可选）：实现 Supervisor 多智能体：一个路由节点按问题类型把任务分发给"检索子图"或"闲聊子图"，并让两路并行执行后在汇总节点合并结果。
