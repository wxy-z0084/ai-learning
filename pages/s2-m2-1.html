路由、请求与响应模型（Pydantic）

预计 1 天模块二 · FastAPI

一、学习目标

  • 能够用 FastAPI 的路径参数、查询参数、请求体三类入参定义路由，说清各自该用什么类型标注。
  • 能够用 Pydantic v2 定义带校验规则的请求/响应模型，并解释校验失败时框架返回 422 的机制。
  • 能够用 response_model 控制出参字段、脱敏与嵌套序列化，选择合适的状态码。
  • 能够用 HTTPException 与自定义异常处理器给出规范的错误响应结构。

二、核心知识点

知识点 1：路由与三类请求参数

一个 FastAPI 应用由若干路由组成：@app.get("/items/{id}") 这类装饰器把「HTTP 方法 + URL 模板」绑定到处理函数，路径中的 {id} 是路径参数，类型标注 int 会自动转换并校验。路径参数之外的入参，FastAPI 按声明位置自动分流：查询参数（URL 中 ?key=value，标量类型如 str/int/bool，默认值即为可选）出现在函数参数列表但未标注为模型；请求体参数标注为 Pydantic 模型类，框架解析 JSON 并校验。同名参数可用 Query(...)、Path(...) 补充描述、别名、范围约束，这些会直接显示进接口文档。

设计约定：URL 用名词、HTTP 动词表达操作——GET 查询、POST 创建、PUT/PATCH 更新、DELETE 删除；GET 应无副作用且可缓存，POST 用于有副作用的写操作。路由顺序也重要：更具体的路径（/users/me）要注册在通配路径（/users/{id}）之前。

知识点 2：Pydantic v2 模型与校验

Pydantic 是基于 Python 类型标注的数据校验库，FastAPI 用它同时承担「入参解析」与「出参序列化」。定义一个 BaseModel 子类、声明字段类型即得：请求里缺字段、类型不对、超出约束都会产生结构化的 422 校验错误，业务代码拿到的一定是合法对象，不必再手写 if 判断。常用增强：Field(min_length=1, max_length=200, description="...") 加约束与文档；str | None = None 表示可选字段；model_config = ConfigDict(extra="forbid") 拒绝未知字段（防拼写错误与参数注入），或用 extra="ignore" 忽略；@field_validator 写跨字段/格式自定义校验（如密码确认一致性、URL 前缀检查）。

常见坑：可变默认值与 None 的处理——可选字段写 x: str | None = None，不要漏默认值导致必填；字段名与 Python 关键字冲突时用 alias（如 model_config populate_by_name=True）。

知识点 3：响应模型与状态码

response_model 决定出参结构：即便内部对象有 10 个字段，声明为只含 3 个字段的响应模型即可过滤多余字段（比如绝不把 password_hash 吐给前端），还能做类型转换与嵌套裁剪。返回值会被自动序列化成 JSON。状态码：200 成功（默认）、201 资源创建成功、204 无内容、400 请求有误、401/403 未认证/无权限、404 资源不存在、409 冲突（重复创建）、422 校验失败（FastAPI 自动生成）、500 服务端异常。用 Response(status_code=201) 或装饰器的 status_code 参数设置。

知识点 4：错误处理

业务错误用 raise HTTPException(status_code=404, detail="用户不存在")，detail 会成为响应体的 detail 字段。要统一全站错误结构（如 {code, message, data}），用 @app.exception_handler 注册自定义处理器，或继承 RequestValidationError 批量改写 422 的格式。原则：detail 面向开发者、可具体；对外信息面向用户、不泄露内部实现（不要把堆栈、SQL 返回给调用方）。

三、示例演示

示例一：完整的小型用户 API，覆盖路径参数、查询参数、请求体、状态码与响应模型：

from fastapi import FastAPI, HTTPException, Query, Response
from pydantic import BaseModel, Field, ConfigDict

app = FastAPI(title="用户服务")

class UserCreate(BaseModel):
    name: str = Field(min_length=1, max_length=50, description="用户名")
    email: str = Field(pattern=r"^[\w.+-]+@[\w-]+\.[\w.]+$")
    password: str = Field(min_length=8)

class UserOut(BaseModel):
    id: int
    name: str
    email: str
    model_config = ConfigDict(from_attributes=True)  # 允许从 ORM 对象读取

FAKE_DB = {1: {"id": 1, "name": "alice", "email": "a@x.com",
               "password_hash": "secret-hash"}}

@app.get("/users", response_model=list[UserOut])
def list_users(limit: int = Query(10, ge=1, le=100), offset: int = 0):
    """查询参数：limit 必须在 1..100，否则 422"""
    rows = list(FAKE_DB.values())[offset: offset + limit]
    return [UserOut(**{k: v for k, v in r.items() if k != "password_hash"})
            for r in rows]

@app.get("/users/{user_id}", response_model=UserOut)
def get_user(user_id: int):
    if user_id not in FAKE_DB:
        raise HTTPException(status_code=404, detail="用户不存在")
    return FAKE_DB[user_id]

@app.post("/users", response_model=UserOut, status_code=201)
def create_user(payload: UserCreate, response: Response):
    if any(u["email"] == payload.email for u in FAKE_DB.values()):
        raise HTTPException(status_code=409, detail="邮箱已被注册")
    new_id = max(FAKE_DB) + 1
    FAKE_DB[new_id] = {"id": new_id, "name": payload.name,
                       "email": payload.email,
                       "password_hash": "hashed:" + payload.password}
    response.headers["Location"] = f"/users/{new_id}"
    return FAKE_DB[new_id]

示例二：自定义校验与统一错误结构，让 422 与业务错误返回同一种格式：

from fastapi import FastAPI, Request
from fastapi.exceptions import RequestValidationError
from fastapi.responses import JSONResponse
from pydantic import BaseModel, field_validator

app = FastAPI()

class QueryReq(BaseModel):
    question: str
    top_k: int = 5

    @field_validator("top_k")
    @classmethod
    def top_k_range(cls, v: int) -> int:
        if not 1 <= v <= 50:
            raise ValueError("top_k 必须在 1~50 之间")
        return v

@app.exception_handler(RequestValidationError)
async def validation_handler(request: Request,
                             exc: RequestValidationError):
    return JSONResponse(
        status_code=422,
        content={"code": 422, "message": "参数校验失败",
                 "errors": exc.errors()},
    )

@app.post("/search")
def search(req: QueryReq):
    return {"code": 0, "data": {"question": req.question,
                                "top_k": req.top_k}}
💡 提示：开发时访问 /docs（Swagger UI）或 /redoc 可以看到自动生成的接口文档——字段描述、约束、示例都来自你的类型标注与 Field，写好模型即写好文档。
